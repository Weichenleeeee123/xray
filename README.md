把钱、时间或信任交给一家公司之前，我们往往已经看过很多资料，却仍然不知道：**这是不是同一家公司？它说的和记录对得上吗？还有什么必须问清楚？**

企er 从一个公司名称和一句真实需求出发，汇集企业相关记录，对照宣传、协议和对方回复，整理成一份能追溯依据的研究报告。小企陪你读懂报告；有了新材料，还能继续补充，查看判断如何变化。

项目代号 **X-Ray（透视·真相）**，为回响 48H 黑客松杭州银行赛题作品。本仓库包含研究室首页、报告与助手、数据汇集和规则分析后端，以及路演与品牌材料。

## 从“查到信息”到“知道该问什么”

一次企业查询通常只能回答“有什么记录”。实际做决定时，更难的是把记录和自己的处境联系起来：一家公司的登记信息，对求职者和准备付款的客户意味着不同的事；宣传里的集团背景，也不一定能说明签约主体的情况。

企er 把这段研究过程放进同一份案卷：

| 你关心的事 | 企er 提供的帮助 |
|---|---|
| 公司名太相似，怕查错对象 | 支持全称与简称查询；存在候选时先确认企业主体 |
| 官网、宣传和协议各说各的 | 将材料中的资质、背景、收益、收款与退款等说法和记录逐项对照 |
| 资料很多，不知道先看哪里 | 根据需求调整报告关注点，整理风险、财务、信用、口碑四个信号 |
| 看到了提示，但不知道依据 | 展示记录、来源类型、资料日期与可用的原始链接 |
| 对方给了新回复，之前的报告怎么办 | 补充进同一案卷，生成新版本，并保留变化原因与旧版依据 |
| 想和家人或柜员一起讨论 | 提供面向不同读者的一页结论，支持浏览器打印 |

## 哪些时候可以用

当前提供六类研究场景。需求可以直接用日常语言描述，不必先懂工商、财务或金融术语。

| 场景 | 可以这样问 | 主要关注 |
|---|---|---|
| 存钱、理财、投资 | “家人想在这里买理财，担心急用时取不出来。” | 机构资质、产品与承诺、资金去向、退出条件 |
| 求职入职 | “收到这家公司的 offer，入职前想再了解一下。” | 用工主体、经营记录、招聘说法、押金或培训费 |
| 预付消费 | “准备买一年课程，想先看退费和经营情况。” | 收款主体、退款约定、经营与投诉记录 |
| 合作签约、付款 | “准备给这个供应商付定金。” | 签约与收款主体、公开信用记录、合同中待确认事项 |
| 接手、入股企业 | “有人邀请我入股，想先梳理公开资料。” | 企业背景、股权、公开财务信息和经营责任线索 |
| 一般了解 | “想先了解这家公司。” | 登记、资质、公开记录与尚未覆盖的信息 |

这些是研究关注点。实际可获得的资料取决于企业披露情况、数据源配置和当次查询结果。

## 一次完整的使用过程

**1. 说清对象与需求。** 在小企研究室输入企业名称，填写你准备做什么、最关心什么。需求也可以留空，从一般企业信息开始。正式首页不上传材料；初版报告只围绕企业资料分析。合同、宣传截图及对方回复，在案卷中通过独立的“材料分析”核对。

**2. 看研究过程，打开案卷。** 小企在办公室场景中随着后端研究阶段移动。报告保存并核对完成后，可点击桌面报告册或就绪入口查看。刷新页面可以继续查看同一次查询。

**3. 阅读结果，追溯证据。** 先看与需求有关的提示，再查看四个信号、材料核对结果和资料来源。报告会区分查到记录、未查到、尚未查询和查询失败。

**4. 问小企，补充新情况。** 可以问“这条依据是什么”“还有哪些没查到”“下一步该问对方什么”。对方回复或新协议可以加入案卷，重新分析后查看新旧版本的变化。

**5. 带着问题继续沟通。** 打印一页结论，将已知事实、疑点、缺口和下一步问题带给家人或网点柜员。

具体按钮、材料要求与常见问题见 [使用指南](docs/product-guide.md)。

## 报告里有什么

报告采用黄铜蓝柜配色，以海军蓝、纸张米白和黄铜色组成办公室档案的视觉风格。章节导航帮助你从概览进入细节，小企助手可以在阅读时展开。

| 报告内容 | 怎么读 |
|---|---|
| 企业概况与五维雷达 | 摘要按需求突出已查企业发现，不输出高低信任评级；记录分类与雷达保留原始定性状态，材料及用户评价不参与企业概况 |
| 四个信号 | 从风险、财务、信用、口碑查看相关记录，结合自己的需求判断哪些值得继续核实 |
| 材料核对结果 | 看“它怎么说”和“记录怎么写”，区分相符、存在出入与无法核实 |
| 问询与复核 | 把信息缺口变成可以向对方提出的问题，补充材料后继续研究 |
| 详细信息 | 按当前数据查看时间线、股东、资本等信息及用户评价 |
| 资料来源与版本变化 | 回到支撑条目的记录，查看数据日期；补充后查看哪些判断改变以及原因 |

没有取得的数据会保留缺口，不用空白或图表代替事实。用户评价单独标注为未核实的个人意见，不作为一页结论中的企业事实。

## 小企：陪你读报告的助手

小企围绕当前案卷和正在查看的报告版本回答问题。你可以直接提问，也可以选中报告里的条目再问。回答中的引用关联相应版本，便于回到当时的依据。

模型负责识别需求、提取材料中的说法、解释与问答；核心核对状态由规则结合记录生成。程序会校验引用编号和逐字引文。**聊天不会直接改变报告**：新信息需要通过“加入案卷”或“补充信息”提交，才会生成新版本。

未配置模型或相关能力不可用时，系统会按可用能力提供关键词识别、模板回答或手动补充提示。

## 证据从哪里来

企er 会保留不同来源的身份，帮助你判断一条信息的分量和时效。

| 来源 | 覆盖内容与条件 |
|---|---|
| 官方公开名单与披露 | 金融机构、私募管理人等名单，以及可获得的年报、公告等；本地名单有快照日期，部分详情按需获取并缓存 |
| 商业企业数据 | 配置相应服务后查询登记、股东、经营与司法相关记录等；能力、额度与数据覆盖由提供方决定 |
| 联网检索 | 配置模型网关后检索相关官方文件与网络报道；保留出处和主体匹配提示，搜索结果不等于完整数据库 |
| 人工采集证据 | 项目组整理的公开文书、年报和其他材料，带来源与日期 |
| 用户提交材料 | 宣传、协议、截图、对方回复等；作为待核对材料，不自动视为事实 |
| 用户评价与演示数据 | 评价标明未核实；虚构企业和记录明确标注为演示 |

完整接入配置见 [后端说明](backend/README.md)。企业信息可能更新，报告应结合记录日期阅读；“未查到”仅描述本次覆盖范围内的结果，不代表不存在相关问题。企er 不提供企业安全评分，也不代替投资、法律或其他专业判断。

## 案卷与隐私

当前使用免登录的浏览器访客身份。案卷、提交的材料、研究任务和聊天按访客隔离，其他访客不能仅凭案卷链接读取内容。**案卷数据保存在服务端，并非只保存在你的浏览器里**；访问身份由浏览器 Cookie 维持。

换设备、换浏览器、清除 Cookie 或身份失效后，不能自动恢复原案卷，目前不提供账号同步。只有主动提交的用户评价进入公开评价区。启用外部模型或查询服务时，相关处理会使用配置的服务，不能把它视为完全离线或端到端加密的系统。

部署者应保存访客签名密钥，配置 HTTPS，并妥善管理服务端数据目录。密钥、用户案卷和运行缓存不纳入本仓库；部署细节见 [部署与维护](docs/deployment.md)。

## 快速开始

需要 **Python 3.11+**、**Node.js 22.13+**。以下命令在仓库根目录开始，使用 Windows PowerShell。

先安装首页依赖并构建静态入口：

```powershell
cd research-room
npm install
npm run build:home
cd ..
```

再安装后端并启动。已有 `.env` 时保留原配置：

```powershell
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-b.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

打开 [小企研究室](http://localhost:8000)，接口文档在 [本地 API 文档](http://localhost:8000/docs)。FastAPI 同源提供首页、报告、静态资源和 API；首页修改后需重新执行 `npm run build:home`，该构建配置保留输出目录中的已有文件。

不填 API Key 也可以运行，但只使用当前可用的本地资料和规则能力；商业查询、联网检索与图片理解等能力需要相应配置。不要把缺少配置的运行结果当作完整企业调查。

| 要启用的能力 | 主要配置（`backend/.env`） |
|---|---|
| 模型理解、解释与问答 | `TOKENDANCE_BASE_URL`、`TOKENDANCE_API_KEY`、`TOKENDANCE_MODEL` |
| 图片理解 | 上述网关及 `TOKENDANCE_VISION_MODEL`，需要模型支持看图 |
| 企查查智能体平台 | `XRAY_COMMERCIAL=qcc_agent`、`QCC_AGENT_KEY` |
| 模型工作模式 | `XRAY_LLM_MODE=live` / `replay` / `off` |

更多配置、第三方用量和数据目录说明见 [backend/README.md](backend/README.md)。

### 开发与验证

开发研究室时，保持后端运行，另开终端：

```powershell
cd research-room
npm run dev -- --port 3000
```

访问 [首页开发预览](http://localhost:3000)。默认转发到 `http://127.0.0.1:8000`，其他后端地址可通过 `research-room/.env.local` 的 `XRAY_BACKEND_URL` 设置。生产默认采用前述单服务部署；独立 Worker 方案见 [首页接入说明](docs/research-home-integration.md)。

在仓库根目录运行前端测试：

```powershell
node --test web/tests/*.test.cjs
node --experimental-strip-types --test research-room/tests/*.test.mjs
```

在 `backend` 目录运行后端测试（先完成首页构建）：

```powershell
.venv\Scripts\python -m pytest
```

默认测试不需要真实服务 Key。调用在线模型、商业数据或执行在线验收脚本会产生相应服务用量，具体命令见后端说明；测试数量以当前运行结果为准。需要保留全部测试文件时，为 pytest 指定从未使用过的 `--basetemp`，并设 `-o tmp_path_retention_count=999 -o tmp_path_retention_policy=all`。

## 演示与路演材料

项目提供 A、B 两个真实企业研究案例和 C 虚构企业案例，分别用于展示材料核对、求职场景和连续补充分析。真实企业案例应按资料日期解读，路演前核对原始证据；不要预设某条结论一定出现。

三种演示方式有不同用途：

| 方式 | 前提与范围 |
|---|---|
| 预制案例包 | 提前生成指定示例及预备补充的各版报告；精确匹配预设输入时回放已有研究过程，改动输入则转入正常研究。包不随仓库分发，生成与检查见后端说明 |
| 模型响应回放 | `XRAY_LLM_MODE=replay` 使用已有且匹配的模型缓存；不等于关闭所有数据源网络请求，也不保证任意新问题可用 |
| 静态备用页 | 本地 `/demo/` 是早期固定演示，用于备用展示，不执行完整研究流程 |

预制报告不包含任意小企问答的离线保证；现场应明确说明展示的是实时查询还是预先准备的结果。

- [五分钟产品路演 PPT v04](output/pitch-product/企er-产品路演-5分钟-v04.pptx)、[逐页讲稿](output/pitch-product/逐页讲稿-5分钟.md) 与 [上台操作卡](output/pitch-product/上台操作卡.md)：主线讲产品解决什么问题、如何工作和差异点，案例只用约 35 秒证明功能。
- [路演操作单](docs/demo-runbook.md)：讲述顺序、材料准备和现场检查；界面入口以当前使用指南为准。
- [性能与部署记录](docs/2026-10-03-performance-and-deployment.md)：首页加载的测量条件、剩余网络延迟和已发布版本。
- [证据采集清单](docs/evidence-collection.md)：真实案例的原始资料核对。
- [品牌配色规范](docs/2026-10-03-qier-color-palette.md)：黄铜蓝柜配色与已确定的鹅图标。
- [五版易拉宝视觉稿](output/visual-directions/qier-rollup-5/README.md)：80 × 200 cm 比例的候选方案，尚非印刷成品。
- [三版横向封面对比](output/visual-directions/qier-covers-3/comparison.jpg)：16:9 候选方案，均保留供选择。

## 项目结构

```text
research-room/  研究室首页、办公室场景与任务进度交互
web/            报告、案卷、小企助手、材料补充与打印界面
backend/
  app/          FastAPI、数据汇集、规则分析、材料读取与问答
  data/         公开名单、证据包与演示输入；运行数据另行保存并忽略提交
  tests/        后端测试
  tools/        数据更新、演示预制与验收工具
demo/           早期静态备用演示
docs/           产品、使用、开发、部署与路演文档
output/         品牌与视觉探索材料
```

首页用 React / TypeScript 构建；报告端采用原生 JavaScript；后端使用 Python / FastAPI。数据结构以 [`backend/app/models.py`](backend/app/models.py) 为准，判断规则位于 [`backend/app/analysis/`](backend/app/analysis/)。

第一次使用，读 [产品使用指南](docs/product-guide.md)；参与开发，读 [后端说明](backend/README.md) 和 [首页接入说明](docs/research-home-integration.md)；查找完整资料，从 [文档索引](docs/README.md) 进入。
