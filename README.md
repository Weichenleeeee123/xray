# 企er · 透视·真相（X-Ray）

把钱或信任交给一家公司之前，输入它的全称，再说一句你要做什么，比如"我妈想在这家公司存 20 万理财，最怕急用时取不出来"。企er 会把散在各处的真实记录汇到一个案卷里，拿去对照这家公司自己的说法，按你的需求出一份看得懂的报告。每条结论都能点开原始数据。看不懂可以问小企（AI 助手）；有了新情况补充进来，会出新一版报告，并标出哪里变了、为什么变。

回响48H 黑客松作品，赛题是杭州银行「X-Ray | 透视·真相」。

## 底线

- **结论来自规则和记录，不来自模型。** 判定全部由 `backend/app/analysis/` 里的确定性规则给出，同样的输入永远得到同样的结论。模型只做四件事：认需求、读材料、说人话、答问题。
- **没查不等于没问题。** "查到了""查了没有""没查""查询失败"分开显示。
- **不打安全分，不说"诈骗"。** 只说查到了什么、哪里对不上、还不知道什么、下一步该问什么。
- **小企说的话程序要校验。** 出处 id 必须在案卷里，引文必须在原文里逐字找得到，否则丢掉。小企在对话里不能改报告，要改就"加入案卷"重新分析。
- **不给真实公司编负面材料。** 虚构公司全程挂"演示数据 · 公司为虚构"。

报告只是把公开记录摆在一起，不是对这家公司的安全担保，也不是投资建议。

## 快速开始

需要 Python 3.11 以上（本机用的 3.12）和 Node 22.13 以上。首次启动或研究室页面更新后，先构建首页：

```powershell
cd research-room
npm install
npm run build:home
cd ..
```

构建不会清空已有文件。之后只需运行后端，它会同时提供首页、报告、图片和 API：

```powershell
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-b.txt
copy .env.example .env      # 填模型网关和企查查的 Key；不填也能跑
.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

打开 http://localhost:8000 即为正式的小企研究室首页。入口沿用队友原版：公司全称、开始查询按钮及下方的“研究需求（选填）”。需求留空时了解登记、资质与公开资料；填写时原样交给后端。鹅按后端真实阶段移动，点击桌面卷宗或“报告已就绪”进入报告。右下角菜单提供案卷、使用说明和“附带材料查询”；材料和演示案例可在完整材料表单中填写。原来的报告、问答、评价和版本功能保留。

队友继续开发研究室时，可以保持后端运行，另开独立热更新预览（正常使用不需要这个进程）：

```sh
cd research-room
npm run dev -- --port 3000
```

打开 http://localhost:3000 。开发预览默认后端为 `http://127.0.0.1:8000`；使用其他端口时，可在 `research-room/.env.local` 中设置 `XRAY_BACKEND_URL`。正式首页通过同源的 `POST /api/runs` 创建任务、`GET /api/runs/{id}` 读取真实阶段，再读回案卷确认保存。查询后输入框隐藏，暂停只控制动画。查询编号记在地址栏（`?run=…`），刷新页面会接着看同一次查询，不会重新提交；断线后可“继续查看本次查询”。`?animationTest=fast` 等本地入口仅供合成事件测试。完整映射见 [首页接入说明](docs/research-home-integration.md)。

- 不配 Key 也能用：规则照常出结论，需求识别退回关键词，小企退回模板回答，工商登记显示"没查"。
- 测试：先构建首页，再在 `backend` 里跑 `.venv\Scripts\python -m pytest`（不连网、不扣费，数量以运行结果为准）；仓库根目录跑 `node --test web/tests/*.test.cjs`（27 个）。研究室另有 `node --experimental-strip-types --test research-room/tests/*.test.mjs`（26 个；Node 22.18 以上可省掉这个参数）。
- 断网演示：`.env` 里设 `XRAY_LLM_MODE=replay`，只用录好的模型响应，界面标"离线回放"。

配置项、接口和数据来源的完整说明见 [backend/README.md](backend/README.md)。

## 数据：哪些是真的

| 数据 | 来源 | 报告里标 |
|---|---|---|
| 银行业、保险、期货、支付机构名单，私募基金管理人全量 | 金融监管总局、证监会、人民银行、中基协公开名单，已整份入库 | 官方记录 |
| 中基协详情页（规模、员工、诚信信息、处罚） | 公开页面，实时取、有缓存 | 官方记录 |
| 监管、法院、政府网站上点名这家公司的文件 | 接了模型网关才联网搜，只留摘要里有公司全称的 | 官方记录 |
| 投诉、维权、兑付相关的公开报道 | 同上，全网搜；只对上简称的标"可能是同名的别家" | 网络公开 |
| 工商登记、股东、分支机构、上市信息、处罚、被执行、失信、限高、经营异常 | 企查查智能体数据平台，配了 Key 才查 | 商业数据（有出入以官方公示为准） |
| 财务数据（上市、发债等公开财报的公司才有）、新闻舆情、实际控制人、许可资质、变更、开庭立案、劳动仲裁、招聘 | 同上；新闻的"负面"是企查查标的，不是我们的判断 | 商业数据 |
| 上市公司年报原文和公告 | 巨潮资讯网（证监会指定披露网站），免费 | 官方记录 |
| 人民网、新华网、财新、证券时报等权威媒体的报道 | 接了模型网关才联网搜 | 网络公开 |
| 项目组人工摘录的文书、年报 | `backend/data/evidence_packs/` | 人工采集 |
| 3 家虚构公司的全部记录 | `backend/data/fixtures/` | 演示 · 虚构 |

## 演示案例

| 案例 | 公司 | 需求 | 用来讲什么 |
|---|---|---|---|
| A | 杭州巨鲸财富管理有限公司（真实） | 我妈想存 20 万理财 | 它说有信托、证券、期货等牌照，名单里只查得到私募登记；20 万够不上私募门槛；改成 120 万后看结论怎么变 |
| B | 杭州银行股份有限公司（真实） | 收到 offer，想知道靠不靠谱 | 同一套方法换个需求，看的重点跟着变；正规公司的说法大多和记录相符，处罚记录也照样列出 |
| C | 杭州满盈禾康养健康咨询有限公司（虚构） | 我妈想存 20 万理财 | 补对方回复、协议、无关材料、改需求，演示二次分析和断网兜底 |

案例 A 的失信被执行人、限制高消费、经营异常来自企查查商业数据。上台讲之前，必须先到官方网站截图核实，见 [证据采集清单](docs/evidence-collection.md)。

## 目录

```text
backend/        FastAPI 后端：规则、数据汇集、报告、小企
  app/          代码；models.py 是前后端共用的契约
  data/         名单、证据包、真实材料、虚构演示数据；cases/、cache/、reviews/ 运行时生成，git 忽略
  tests/        后端测试
  tools/        更新名单、探测网关、浏览器验收的脚本
web/            前端：原生 JS，不打包，由后端同端口挂载
demo/           早期的静态演示页，断网时的最后备用（/demo/）
research-room/  正式研究室首页；静态构建由后端根路径提供，按 /api/runs 的真实阶段驱动动画，报告复用 /xray/ 页面
docs/           文档，先看 docs/README.md
```

## 隐私

仓库是公开的：
- Key 只放在被 git 忽略的 `backend/.env`。
- 法定代表人、负责人、联系方式不存。自然人股东写成"自然人股东A"，处罚文书里的个人写成"相关个人"。
- 用户写的评价、案卷、模型和企查查的缓存都在被忽略的目录里，不进仓库。
