## API 和配置变化

- 并发提交冲突：HTTP 409，刷新案卷后重新提交。stream/run 的错误事件也标记 409。
- `GET /api/cases?limit=100&offset=0`：默认最多 100 条，limit 最大 500。响应仍是原列表格式。
- `GET /api/cases/{id}/versions/{no}`：只返回选定版本及其原始记录、来源目录。
- CaseIn、SupplementIn 可传 `refresh_sources: true`，本次绕过商业缓存，可能产生新费用。
- 建案、补充的 `/runs` 接口可带 `Idempotency-Key`。同一路径同一键复用 run_id；相同键不同内容返回 409。失败任务需要新键才会重新执行。
- `XRAY_COMMERCIAL_CACHE_TTL=86400`、`XRAY_MAX_RUNS=4`，见 `backend/.env.example`。没有修改实际配置文件。
- 存储多出 `.lock` 和 `summaries/`，任务多出 `.lease`、`requests/`；这些是运行时数据，旧文件无需迁移即可读取。

## 明确的边界

本轮解决已复现缺陷，并非把审计报告中全部长期建议一并实现：

- 仍是单机文件存储。费用与执行并发上限是**每进程**，不是跨实例/租户共享账本；预算会随进程重启重置。跨进程文件提交和同键缓存填充有互斥，但正式多实例仍需数据库/统一预算服务。
- 服务异常退出后，租约到期显示 interrupted，**不会自动续跑或重新计费**；优雅停止只等待现有任务，未引入可抢占进程、断点恢复和独立队列。同步/stream 入口不承诺请求幂等，需重试保障的客户端使用 `/runs` 和键。
- 过期查询失败时保留磁盘旧缓存，本次标未查/失败，不把旧结果冒充本次事实；没有实现把旧结果与失败状态一起展示的 stale-if-error 视图。
- 事实选择和保守校验降低模型反转风险，不证明任意自然语言都与证据语义等价。复杂主体、引述、条件、历史时态，以及多份合同分域，仍需更完整的数据模型和评测集。
- 新写缓存遵循脱敏路径，历史缓存没有批量清理；未来读取到有效的旧 QCC 缓存时会尝试就地脱敏。名称/摘要的自由文本脱敏不是完整 DLP。
- 列表已索引、分页，原全案卷详情接口保持兼容，聊天仍原子重写 Case；大规模历史拆表、检索式上下文没有混入这轮小改动。
- 没有新增多租户账号、权限体系、评价审核、正式分享，也没有部署、升级依赖或联网验收付费接口。这些属于审计第 5–6 节的上线和功能项目。
