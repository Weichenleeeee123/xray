# 大案卷追问：无损压紧上下文

公网真实流程生成的一个求职案卷包含 60 条来源。普通问题“劳动合同的签约主体有哪些依据，还缺什么材料”在调用模型前被 120,000 字符上限拒绝。原因是完整版本里的来源目录、词表与顶层内容重复，普通 JSON 分隔符也占用空间。

新逻辑先生成旧格式。预算以内保持原请求字节布局，兼容已录制的小案卷回答；超过预算才把同一来源目录、完整词表集中为一份，并使用紧凑 JSON。不会筛选或截断原始记录，也不会删除报告中的争议、反证、未知项和规则判定。仍超限时如实拒绝，不偷偷把部分材料交给模型。

实际授权测试案卷由 132,532 降至 113,937 字符，减少 18,595。60 条原始记录、来源、完整词表和报告其余字段逐项相等，案卷未变。这里只沿用原有契约：不向模型重复发送易变的抓取时间；这些时间仍保留在案卷/API。新增但为空的 `prebuilt` 字段也从旧格式省略，实际快照元数据仍保留。

验证：TDD 12 项先失败后通过，相关测试 159 项通过，独立复审 53 项通过；后端全量 509 项通过（一个既有 Starlette 测试客户端弃用提示）。测试中真实 60 条案卷从未进入模型的 guard，变为调用一次模拟模型。旧格式实际录制后以 replay 模式命中的回归测试通过。公网真实模型响应另记发布验收，不把模拟响应称为在线成功。

上限是字符预算，并非模型 token 上下文窗口承诺。大幅增加材料仍可能超限；选择某一条只帮助明确问题，不保证缩小完整上下文。
