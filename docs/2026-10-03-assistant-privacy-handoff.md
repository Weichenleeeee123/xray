# 小企回答与私有案卷改造交接

## 发布核对

工作基线：`895bcf0`，保留队友最新的小企动画及品牌图标。
本机修改和 Git 推送不会自动部署公网；由部署队友发布。

发布必须一起更新后端、`web/`、`research-room/public/` 和重新构建的
`research-room/home-dist/`，不能只覆盖一个脚本。保留服务器现有运行数据。

服务器私有配置需要核对以下非密钥项（不覆盖原有密钥）：

```dotenv
TOKENDANCE_MODEL=qwen3.8-max
TOKENDANCE_VISION_MODEL=qwen3.8-max
TOKENDANCE_ENABLE_THINKING=0
XRAY_RELEASE_ID=<实际部署的提交号>
```

重启后检查 `/api/health` 中的 `llm.model`、`llm.vision_model`、
`llm.enable_thinking` 和 `deployment`。`release_id=null` 表示未填写发布标识，
不是已验证的最新版本。`report_asset` / `home_asset` 是实际文件 SHA-256 前 16 位。
再确认报告脚本、首页产物和品牌资源可访问；不能仅凭健康接口 200 验收部署。

对外不要复制原始日志、模型缓存或用户材料。所有后续的用户材料、案卷、聊天
必须私有；公共评价只来自用户主动填写并提交的评价，不从上传材料自动发布。

## 访客隐私隔离（用户已确认）

- 无需登录，HTTPS 使用 `__Host-qier_guest` 签名、HttpOnly、Secure、SameSite=Lax Cookie。
- 服务端案卷记录不可逆的 owner_id；案卷列表、版本、原文、聊天、补材料、判断修改、查询进度和恢复输入均核对归属。响应不暴露 owner_id。
- 查询幂等键按访客隔离。跨浏览器、清除 Cookie 或失去签名文件后不能自动认领案卷。
- 没有 owner_id 的旧案卷及旧任务一律隐藏，原文件不删除、不自动分配给第一个访问者。未来的管理员迁移必须先核实归属。
- 公共评价只能通过明确的评价提交接口创建；评价作者绑定签名访客身份，不能靠请求参数冒充别人。
- API 响应 `private, no-store`，跨站写请求拒绝；不再使用通配 CORS。
- 设置 `XRAY_PRIVATE_DIR=/var/lib/qier/private`，必须与 `/var/lib/qier/cases` 等运行数据一起持久化。签名文件权限仅服务账号可读；不要提交或公开备份。
- Caddy / CDN 不得覆盖 API 的 no-store、忽略 Cookie 或缓存 Set-Cookie 响应。代理必须透传 Cookie / Set-Cookie，HTTPS scheme 应由受信代理传给 Uvicorn。
- 独立前端代理部署需设置精确 `XRAY_ALLOWED_ORIGINS`，同源生产不用设置；不能信任任意客户端传来的 X-Forwarded-Host 来放行跨站请求。
- 用户界面说明“仅此浏览器可见”，不把历史案卷消失说成删除。管理员/服务器运维仍可读取服务器文件，外部模型供应商仍会处理必要材料；这不是端到端加密。

## 回答溯源与审计

聊天正文只保留答复及建议，右下角“原文出处”打开对应历史版本的引用清单。
完整引文及采集时间在来源详情中查看，表格原文也能高亮。重复引用去重；纯安慰无伪造出处。
`blocked`、`dropped`、`rewrites` 仍留在服务器案卷内用于排查，但普通问答与案卷 API 的响应 DTO 不返回这些内部诊断字段。

## 回答内容与等待恢复

- 企业事实、情绪回应、用户自述、行动/澄清分别校验；不要求安慰语附上企业出处，不允许以 support 标签夹带企业保证。
- 金额由程序从用户消息解析，保留 Decimal 计算；企业数字、原文逐字、出处、报告版本与确定性规则校验不变。引用真实但不相关的报告 ID 不能支持新事实。
- 事实优先选 fact_id，服务端用报告既有解释呈现，模型不能修改内容。较早响应格式继续可读，新模型输出不再请求一篇重复的 answer 长文。
- 基于问题侧重点选择先澄清业务或解释案卷，案卷原文仍完整进入上下文，不通过截断资料来提速。
- 行动目录只包含核对步骤和澄清问题，不是新的金融法律知识库。现有案卷词表的来源与适用时效仍需按原流程维护。
- `XRAY_CHAT_TIMEOUT=60`：后续模型调用、JSON 修复和事实重写共用时间预算；HTTP 操作超时随剩余预算缩短。这是重试预算，不保证已经发出的网络调用瞬间取消。
- 前端问答 90 秒停止等待，提供主动停止与恢复结果；不会自动重复 POST。
- 问答支持 `Idempotency-Key`，按访客＋案卷隔离；完成后的同键同请求返回已保存答案，同键不同问题 409，处理中重复请求 409。
- `GET /api/cases/{id}/chat/requests/{request_key}` 只允许所有者恢复状态及已校验回答。停止前端等待不等于停止后台；失败或中断状态不会伪装成成功。
- 临时恢复状态只保存在当前标签页 sessionStorage，身份凭证始终为 HttpOnly Cookie，不写入 localStorage。

## 验收记录（2026-10-03，本机，不代表已公网发布）

真实 Tokendance / qwen3.8-max、关闭长思考，以虚构演示案卷做三轮对话：

1. “我想存20w但好害怕怎么办”：4.55 秒，mode=model，自然回应担忧，正确复述20万元，澄清产品类型；无假出处、无校验重写。
2. “我主要是怕急用时取不出来，应该先问什么”：8.23 秒，mode=model，给出退出时间和扣费条款的具体问法；有2次校验重写，未放宽校验。
3. “案卷里的保本保息为什么要留意”：4.88 秒，mode=model，使用A2和词表等已核对出处解释；无校验重写。

以上只说明这三次合成场景的实测结果，不是延迟SLA或真实企业可靠性评估。没有上传真实用户合同或调用付费商业查询。
