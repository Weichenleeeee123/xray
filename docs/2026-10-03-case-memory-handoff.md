# 小企私有案卷记忆：实现及验收交接

日期：2026-10-03。分支：`codex/xiaoqi-case-memory`。基线：远端 `main` 的 `1e08a4e`。

后续整合说明：以上分支、测试数量和模型对照属于独立开发阶段记录。与最新主线的无损上下文去重、资料库和案卷布局整合后的发布说明见 [整合发布交接](2026-10-03-integrated-release-handoff.md)。

本文件记录本机实现，不表示已推送、合并或部署公网。实现依据用户提供的
`2026-10-03-xiaoqi-case-memory-agent-plan.md`；不训练模型、不换供应商、不修改报告整体视觉。
本轮不包含上一轮待处理的报告悬停配色、雷达文案及案卷布局统一。

## 1. 已实现

1. `app/case_memory/models.py`、`builder.py`：版本化概览、主题卡、证据关系和准确 JSON 路径。
   数字、状态、判断直接来自已保存版本，原始材料不改变；不另调模型做摘要。
2. `store.py`：访客归属、案卷、版本、源指纹、构建器和规则版本组成缓存键。
   使用现有跨线程/进程文件锁与原子写；损坏、失败、缺失时重建。无归属历史案卷不建记忆。
3. `main.py`：统一持久化后置钩子覆盖新建、补材料/需求、人工复核、评价刷新、预制示例首次和下一阶段。
   后台构建最多两个并行任务，沿用受管理的任务生命周期；忙时由首次问答按需构建。
   构建失败不影响已保存报告，不伪造调研进度。
4. `retriever.py`：先鉴权及选择版本，再做问题路由、显式引用、关键词/主题和关联证据扩展。
   支持精确原文读取和同案卷版本差异读取辅助函数；没有另外开放公共记忆接口。
   暂不使用向量库、BM25 或自主多轮工具 Agent。
5. `assistant.py`：接入 `full / shadow / selective`；模型仍为原 Tokendance/Qwen 配置。
   顾虑问题优先自然回应与澄清；企业事实只可引用本次提供/读取的证据。
   完整权威记录仍在验证器一侧，原有引用、逐字引文、数字、状态和越界检查保留。
6. 退款等问题捆绑读取取用、费用、期限、主体及收款对象。用户相关材料整篇读取；
   已引用报告事实的源记录不因首个字段命中就丢掉附页/其他字段。
   输出补齐相关条款的否定和例外；模型格式失败时可返回另经校验的程序摘录，不能误报材料不存在。
7. `web/app.js`：只增加简短“按需核对相关材料”标识；预算/覆盖失败明确不是企业风险结论。
   继续只保留一个右下角原文出处入口，不恢复内部拦截信息或重复引文块。

这是“全量保存、按需读取”，不是“每一轮全量输入”。概览是导航，不是证据，更不是训练后的模型记忆。
私有材料不会自动发布成公共评价，外部模型仍会处理本次发送的必要内容。

## 2. 开关与上线方式

默认保留旧路径：

```dotenv
XRAY_CASE_MEMORY_ENABLED=0
XRAY_ASSISTANT_CONTEXT_MODE=full
```

先做影子检索：

```dotenv
XRAY_CASE_MEMORY_ENABLED=1
XRAY_ASSISTANT_CONTEXT_MODE=shadow
XRAY_CASE_MEMORY_DIR=/var/lib/qier/case_memory
```

影子模式只在本机程序侧构建/检索，最终仍用全量上下文，不额外调用回答模型。
要使公网小企真正使用新路径，部署队友须明确改为：

```dotenv
XRAY_CASE_MEMORY_ENABLED=1
XRAY_ASSISTANT_CONTEXT_MODE=selective
XRAY_CASE_MEMORY_DIR=/var/lib/qier/case_memory
XRAY_ASSISTANT_CONTEXT_CHARS=120000
XRAY_ASSISTANT_EVIDENCE_CHARS=70000
TOKENDANCE_MODEL=qwen3.8-max
TOKENDANCE_VISION_MODEL=qwen3.8-max
TOKENDANCE_ENABLE_THINKING=0
XRAY_RELEASE_ID=<实际部署提交号>
```

不覆盖现有密钥、案卷、签名身份文件或其他配置。私有目录必须持久化，仅服务账号可读写，不能挂到
静态资源、CDN 或公开备份。现有案卷首次提问时可懒构建，不要求迁移或删除原文。
记忆文件的概览/索引/日志同样属于私有派生信息。

发布后检查 `/api/health` 中 `assistant_context.mode`、`memory_enabled`、`llm` 和 `deployment`；
健康接口不返回私有路径、记忆内容或归属。随后用真实 HTTPS 的两个独立访客进行案卷隔离与出处检查。
本机自动测试不能代替公网 Cookie、反向代理及发布产物验收。

回退只需 `XRAY_ASSISTANT_CONTEXT_MODE=full` 并重启；若不再构建记忆，同时设 `XRAY_CASE_MEMORY_ENABLED=0`。
不删除已有记忆，不回滚用户报告。**只更新代码但保留默认配置，不会自动解决公网的大案卷问答拦截。**

## 3. 预算和覆盖边界

- 120000/70000 是本应用的字符防护，不是已验证的 Tokendance 模型 token 上限。
  本轮未取得该网关可核验的最大 token 容量，不通过任意提高上限规避问题。
- 证据预算按完整记录单元计算，系统提示、JSON Schema 和修复另有预留；每次实际 HTTP 请求也检查输入规模。
  保留原问答总时间预算，JSON 修复与事实重写不能分别重置总预算。
- 未知意图或“整体/所有风险”等综合问题扩大到全局目录、卡片及原文，不以 top-k 冒充全面核查。
  超出证据预算时，能放下完整原文才回退 `full`；否则明确覆盖不足，不无限重试。
- 为避免长材料在回答中堆满屏幕，条件摘录按完整句子合并，并保留邻句、显式例外与限制。
  原文输入/存档不据此裁剪。单个摘录超过2900字符、合计超过6000字符或超过12个独立摘录时，
  明确请用户指定条款，不把长句截半或冒充已经完整回答。此输出保守策略后续可做分批核对优化。
- 首版主题及同义词是启发式检索，不保证覆盖所有真实合同的隐含交叉引用；泛化能力仍需更多样本。
  未检索到不等于不存在，引用逐字相同不等于用户宣称真实。

## 4. 自动化及浏览器验收

基线后端440项；本轮最终后端476项通过（新增36项），前端102项通过。
TypeScript检查、首页生产构建、Git空白检查通过。
既有Starlette测试客户端弃用提醒保留；Vite的研究室资源运行时解析提示保留，不将提示隐藏成无警告构建。

新增覆盖包括：

- 双访客记忆隔离、隐藏历史无归属案卷、公开目录拒绝、并发只构建一次、缓存故障重建。
- 版本/源/规则/构建器变化后的失效，旧版本稳定；创建、需求变化、补充、人工复核、评价及预制示例实际入口。
- 显式引用、关联原文附页、退款与不退款条件、长材料完整输入及完整句子输出。
- 合法但未读的ID/叶子不可引用；用户金额不冒充公司数字；错误数字、规则状态、材料提示注入被拦截。
- 模型格式失败不把已有合同说成不存在；整体问题覆盖不足；影子模式不增加模型调用。
- Schema修复不能绕过输入预算；幂等问答、原回复恢复、对外DTO隐藏内部诊断。

Edge两个隔离浏览器上下文，本机隔离临时数据、模型关闭的基础答复模式下验证：

1. 顾虑问题自然回应，不出现伪造出处；显示按需核对标识。
2. 退款回答同时保留不退及扣费条件，右下角出处可打开完整原文。
3. 后端已保存但网络响应延迟时，停止等待→刷新→恢复，仅一次POST、不重复聊天。
4. 加新材料形成第2版，旧回答来源仍打开第1版，旧版本内容不变。
5. 另一访客看不到案卷、直链404；零JavaScript异常。

浏览器基础答复验收与下面的真实模型测试是两组独立测试，不冒充已在公网做了全部验收。

## 5. 真实 Tokendance 对照（合成数据）

固定虚构示例加0/60/400条无关活动记录，原全量上下文约41244/79215/293715字符。
不读取真实用户案卷，不调用企查查或其他商业调查接口。Qwen3.8-Max，关闭长思考。

| 问题/样本 | full | selective | 核对结果 |
| --- | --- | --- | --- |
| 小案卷，合同退款 | 15.29秒，3次调用，输入合计64198 token | 最后复测2.90秒，1次调用，输入9606 token | 新路径保留“服务开始后不退”和费用条件，最终0次重写 |
| 中案卷，我想存20w但害怕 | 3.05秒，1次调用，输入43413 token | 3.35秒，1次调用，输入2150 token | 均回应顾虑、正确复述用户金额，不制造企业出处 |
| 大案卷，同一顾虑问题 | 本地预算拦截，0次调用 | 1.90秒，1次调用，输入2151 token | 新路径正常回答；并未读完整大案卷后作企业结论 |

中等案卷输入减少约95%，**这组样本耗时未减少**。退款调试中也出现7.82秒/2次及11.11秒/3次调用；
不能只凭最后一次2.90秒承诺稳定延迟。早期“已有材料却答没查到”的格式/回退问题已修复并固定为回归测试。
表格只提供少量实际样本，不计算P50/P95，不承诺更准确或固定秒数。

成本按接口usage记录：小案卷full输出合计650 token；最终selective输出109 token；
中案卷两种模式各82 token；大案卷selective输出74 token。调试过程中还有其他重试调用，
这里不是整个开发过程的账单总额；未读取账户扣费/缓存折扣，不能据此报人民币费用。
记忆构建本身0模型调用、0模型token。

最终离线本机测量：小/中/大记忆冷构建约16/23/63毫秒，磁盘热命中约7/7/11毫秒，检索约6/6/9毫秒。
真实对照使用隔离的本地响应缓存、已构建的记忆；服务商是否命中前缀缓存未知。
不要把本机内存/磁盘热命中与服务商模型缓存混淆。
