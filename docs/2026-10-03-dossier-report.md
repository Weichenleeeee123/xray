# 卷宗报告接入正式应用

本次将确认过的牛皮卷宗设计接入 `/xray/#/case/<id>`，不再使用独立预览页的数据和交互模拟。

- 企业概况、四个信号、逐条问询、材料复核、报告版本和资料来源均读取当前案卷及当前版本。问题条数与内容由后端返回。
- 拍照/文件上传、OCR 后确认、回复补充、版本生成、打印、术语解释、收藏与评价继续使用现有应用处理函数和 API。
- 左侧主入口为企业、案卷、知识库、我的，报告目录在其下单独分组；使用说明放在底部。知识库复用既有名词解释收藏和账号同步，不改变存储键与接口。
- 小企在桌面与报告并排；窄屏进入独立行。设计样式按报告状态限定；原始数据、演示标记、未覆盖状态、私有案卷边界和账号功能保留。
- `web/dossier-report.js` 负责真实数据展示，`web/dossier/artwork.js` 仅含装饰图形，`web/dossier/*.css` 继承确认的预览样式，`live.css` 适配真实壳子和响应式布局。
- 保留主分支刚合入的查询首页归一、独立使用说明、晚到场景资料刷新、银行案例上下文修复。

## 验证

- 报告前端自动检查 134 项、研究室首页检查 99 项通过；首页构建成功。
- 后端自动检查 592 项通过，包括报告静态资源、账号、收藏同步、私有案卷、材料及版本相关检查。仅现有 Starlette/httpx 弃用提示。
- 真实 FastAPI 本地验收：使用虚构示例生成报告，补充合同生成第二版并回看第一版；问询详情、原始资本资料、术语解释收藏到知识库并返回所属报告、小企并排布局、390px 手机布局均通过。
- 本地验收关闭在线模型、使用独立临时数据目录，没有调用付费企业数据或模型，也没有把测试案卷/收藏上传仓库。

Git 上传不会自动部署 qier.asia。生产发布仍按 `docs/deployment.md` 构建首页、发布静态资源并复用服务器的私有配置和运行数据。
