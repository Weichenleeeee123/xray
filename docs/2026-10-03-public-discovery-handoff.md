# 企业公开信息扩搜：实现、验收与发布交接

日期：2026-10-03。实施分支：`codex/company-information-coverage`。

本轮依据外层工作区的 `2026-10-03-company-information-coverage-optimization-plan.md` 实施。
本文件记录实际实现和推送前验证，GitHub 合并状态以对应 PR 为准，不代表已经部署。没有修改生产环境文件、账户额度、网关凭据或模型。

## 1. 对方案的理解与实现边界

核心不是再加一个风险报告，而是让相关资料有机会被发现、进入当前版本并被小企使用。
“有材料这样说”“可能属于这个主体”“已经由规则确认”是不同层次。没有官方背书不能成为删除材料的理由；
另一方面，近似关键词命中也不能自动成为该公司的资料。

采用独立的 `web_discovery` 来源通道，保留原来的官方、投诉、媒体和企查查风险输入。
新增资料进入 `Source → RawRecord → Version.raw_ids → 来源目录 → 私有案卷记忆 → 小企`，
不会直接加入旧 `web.news` / `web.official` / `web.media` 的风险计数。

本轮扩搜功能没有改动报告版式、案卷页、雷达、首页导航、研究室角色路线和登录流程；推送前已合入队友最新布局。
现有原文弹窗已经能显示通用结构化字段，所以没有新造一套来源页面。

## 2. 基线与分阶段结果

### P0：基线

开工同步并基于主线 `b34dafe`，保留 PR #14 导航/账户及 PR #15 首问结论/上下文预算修改。
旧联网路径为官方限定域名、简称加负面词、限定媒体域名三路；无一般业务发现及正文核对。
新闻解析原先不保留中立/正面标题；非官方分支会舍弃地方政府网页。
这些是代码确定的盲点，不把它们等同于“公网报告必定漏掉每一个参考链接”。

实施末段的 GitHub 直连超时已在推送前通过本机既有代理恢复，未更改全局 Git 配置。
已无冲突合入最新主线 `385a45c`（PR #16、#17、#18），保留队友的报告/案卷/资料库布局及补充任务刷新恢复。
下文验收计数已经按合入后的完整代码重新验证；未覆盖或重置队友分支。

### P1：直接覆盖

- 保留旧三路；新增全名中性查询、官网/产品、场景业务词、报道/合作/融资、地方政府意图。
- 场景只使用枚举及固定词，不把需求原句、上传文件、私人聊天或付款账户传给搜索。
- 新通道不以旧媒体/政府名单作为接收白名单。域名类别仅用于归因及排序。
- 正面/中立新闻保留实际返回标题；缺失标题仍为空，人名遮盖保留。
- 当前版本包含新增原始记录和来源快照。关掉扩搜开关可回退旧采集路径。

### P2：主动追查

- 按查询上限、并发、总时限执行；成功但主体关联不足，也触发 UniFuncs 补搜。
- 首轮有效结果的供应商分布用于后续名称检索；重复别名不会重复占用查询次数。
- 读取公开页面和同站 about/product/news 链接，再提取品牌/产品/英文名称；不是通过模型记忆补公司关系。
- 确定性提取 + 至多一次受限模型规划；模型只能返回给定页面的名称、URL、连续原文。
  schema、来源 URL、原文、名称字符和关系依据均再核验。失败仍有确定性搜索路径。
- 三个独立维度：主体关联 `direct / linked / possible`；来源性质；正文取得程度。
  `direct` 仅表示材料提及公司；`linked` 是来源支持的名称关系，均不意味着内容真实或经营可靠。
- 同 URL 合并路径和摘要；不同 URL 的相同正文归组但保留链接；不同正文不合并。
- 发布、更新、搜索标注及采集日期分别记录，不从 URL 猜发布日期。
- 读取失败保留摘要；字符/响应体上限导致 `partial`，不会将部分正文标成完整。
- 没有关联线索的近似词结果会记录丢弃原因；不因观点正负或非权威而过滤。

安全：每次连接及重定向重新校验地址，检查全部 DNS 结果并固定连接到已验证的公网 IP，
防止 DNS 重新解析绕过；禁止内网、环回、元数据、非 HTTP(S)、用户口令 URL、非常规端口及 IPv6 转换隧道。
独立无凭据读取器不带网关 Authorization、浏览器 Cookie 或环境代理，不执行脚本，不绕过登录或验证码。
离线回放只使用搜索缓存，不偷偷联网读正文。

### P3：小企和实际浏览器

- 业务、品牌、产品、融资、活动、招聘、媒体进入现有主题索引。
- 新主题卡只是导航，不是新的规则 `fact_id`；必须读取并引用对应原始记录。
- 新网页以完整已取得的页面单元参与检索，关联依据、读取限制与不同说法随资料一起提供。
- 概览只保留紧凑导航，不重复每页关联引文；全文和详细关系仍在原始记录中。
- 引用正文仍逐字检查，数字和规则方向检查未放松；新增公开资料必须有对应原文引用。
- 服务端附来源性质、主体不确定性、读取程度，不能依赖模型自觉加免责声明。
- 大资料超过读取预算时明确报告覆盖不足，不截断材料后冒充完整回答。
- 使用真实 FastAPI + Edge + 前端页面、合成公开响应完成 11 项浏览器检查：
  首页输入、任务幂等、进度事件、当前版本来源、既有来源目录、原文弹窗/链接、小企召回、
  聊天出处、补材料后的历史出处、访客隔离、无浏览器错误。无外部请求。

## 3. 配置、开启与回退

新代码默认 `XRAY_WEB_DISCOVERY=1`，但还必须有可用网关且非 `off` 模式。
这不表示现在公网已启用：需要队友部署新代码并重启服务。

| 配置 | 默认 | 含义 |
| --- | ---: | --- |
| `XRAY_WEB_DISCOVERY` | 1 | 独立扩搜开关 |
| `XRAY_WEB_DISCOVERY_QUERIES` | 10 | 单次扩搜查询计划上限，不包含旧三路 |
| `XRAY_WEB_DISCOVERY_ROUNDS` | 2 | 总轮数，包含首轮 |
| `XRAY_WEB_DISCOVERY_WORKERS` | 3 | 每批并行任务数 |
| `XRAY_WEB_DISCOVERY_SECONDS` | 35 | 扩搜返回总时限，不是整份报告时限 |
| `XRAY_WEB_DISCOVERY_READS` | 8 | 本轮正文读取上限 |
| `XRAY_WEB_DISCOVERY_HOST_READS` | 3 | 单站读取上限 |
| `XRAY_WEB_DISCOVERY_SEARCH_TIMEOUT` | 10 | 单项搜索等待上限，秒 |
| `XRAY_WEB_DISCOVERY_READ_TIMEOUT` | 8 | 单页读取等待上限，秒 |
| `XRAY_WEB_DISCOVERY_PAGE_CHARS` | 12000 | 每页已取得正文存储上限，超过标注部分正文 |
| `XRAY_WEB_DISCOVERY_LLM` | 1 | 允许一次现有模型辅助关联规划 |

`GET /api/health` 的 `web_discovery` 返回开关、搜索是否配置、查询上限、轮数、时限。
这个健康字段不是上游可用性保证；还要新查公司并查看本版 `web_discovery` 来源记录。

回退：`XRAY_WEB_DISCOVERY=0` 后重启。停止新扩搜，既有新增案卷字段、出处和私有索引仍能读取，不删数据。
模型规划单独关闭：`XRAY_WEB_DISCOVERY_LLM=0`，中性搜索、正文、确定性名称提取仍可工作。
沿用已有 `XRAY_CASE_MEMORY_ENABLED` / `XRAY_ASSISTANT_CONTEXT_MODE` 部署设置；未擅自修改现场配置。

## 5. 已知限制与部署验收

- 不是全网爬虫；未新增抖音/小红书站内授权、登录态、视频转写或付费数据库能力。
- 页面正文提取不运行 JavaScript；登录、验证码、异常编码、PDF 等会保留摘要和读取状态。
- 只有精确标准化正文相同才归转载组，不宣称已经识别所有改写转载。
- 总时限后只封存已完成结果，迟到工作不会改变已经返回的案卷。底层 DNS/网络线程可能仍短暂收尾。
- 搜索与正文状态是采集状态；`found` 不等于说法真实，`failed/not_found` 不等于公司不存在风险。
- 小企仍受原证据预算约束。全量资料已保存，过大的全面问题可能要求指定范围；没有删除材料或放宽校验。

部署后：先检查健康开关，用自己新建的访客案卷查一家普通小公司，打开扩搜来源，问业务/品牌问题，
再补材料确认新版本和旧出处，最后用另一个浏览器确认无法读取该案卷。
不要使用他人的私有案卷做验收，也不要为上线删除历史数据或关闭配额保护。
