## 2026-10-04 追加：日常了解与本版报告概览

### 问题与处理

此前只分出了词义解释和模糊投资需求。“听说华为是不是特别厉害呀”“你觉得华为怎么样”“你觉得这家公司怎么样”仍可能没有匹配到证据主题，随后被当成全案核查。大案卷因此在模型调用之前就触发覆盖保护；提高预算不能解决问法与读取范围不匹配的问题。

本次增加 `dialogue_routing.py` 和 `assistant_overview.py`：

- **先给有依据的报告概览，再继续问。** 常见整体印象、介绍、概览问题，以及同版本的概览追问，读取本版已生成的结构化报告，重算需求导向摘要，呈现背景、主要发现、重要异常及未覆盖部分。不是仅反问用户，也不是重读全部原文后给完整调查结论。
- **区分自然交流与事实核查。** “厉害”类问题会区分技术、产品、经营等维度；普通“怎么样”不会机械重复“厉害”的开场。已保存的研究目的继续使用，不反复要求用户重填。
- **不能识别范围时先澄清。** 按需读取模式下，没有命中事实主题、具体引用或明确完整核查要求的模糊问题，不再默认升级为全文审计；不把问题含糊解释成企业风险或资料缺失。
- **具体问题保留原核查。** 金额、退款、资质、财务、安全保证、选中条目、混合具体问题、完整核查等继续走原有证据链与上下文保护。概览后再问退款条件，仍读取关联条件和例外，不能沿用概览替代核查。
- **不借用别家企业记录。** 简称只是当前对话的主体提示，不验证品牌归属；明显切换企业时先确认，子公司、分支机构也不自动共享当前公司的依据。

### 引用、历史与隐私边界

概览只引用选定版本的报告条目和绑定公开记录。私有上传材料与用户评价不变成已核实企业事实；重复编号、失配或缺失出处明确保留核对提示。预制摘要仍复核版本、证据指纹、公开来源和有效内容，不按公司名称套用。全部严重异常保留，长条目不截取有利片段，而是保留完整原条目入口。原案卷、原材料及历史报告均不修改。

新增兼容字段 `answer_kind="overview"`、`answer_scope="report_snapshot"`；前端标注“本版报告概览 / 依据已生成报告”，出处仍放在回答右下角。旧回答不补写新标签或结论。同一秒返回的相同文本改按 `request_id` 区分，避免连续问题的回复被前端误去重；同一请求的重放仍去重。

## 修复内容

1. **词义解释独立于案卷大小。** “什么是存续”“存续是什么意思”“请问存续是什么意思”“怎么理解存续”“能解释一下存续吗”“裁判文书是什么意思”等完整词义问题，使用人工词表直接解释，不调用大模型、不构建整案上下文。只解释概念，不夹带公司的成立时间、金额、状态或结论。
2. **修正错误词义。** 存续不是正常营业的保证；新增裁判文书解释；删除用股权出质、动产抵押条数推断企业缺钱的说法。[官方依据](2026-10-03-glossary-clarity-sources.md) 单独记录。
3. **先确认模糊投资需求。** “我投资这家公司怎么样”先问买股票、购买产品还是直接出资合作，不声称已完成投资评估。具体退款、收益、判赔等问题以及明确选中条目的问题，继续走原证据核对流程。
4. **解释与来源一致。** `ChatMessage` 新增向后兼容字段 `answer_kind` 和 `knowledge_terms`。新回答保存本次采用的词义快照；旧案卷不重写，新问答也不再使用旧的错误人工释义。前端右下角“原文出处”优先展示该回答自己的快照。
5. **明确展示回答类型。** 独立解释标为“名词解释”，需求澄清标为“先确认需求”，不把它们误标为模型异常后的基础答复。原始引用仍收在出处弹窗，不公开拦截内容。

## 未改变的边界

- 用户上传材料、完整案卷、公司规则结论、历史报告都不删除或重写。
- 版本和所选引用合法性检查先于分流；访客所有权仍由 API 校验。
- 普通企业问答的逐字引文、数字、确定性判定、来源和覆盖校验保持原规则。
- “存续是什么意思，这家公司安全吗”是混合问题，不能只答词义后冒充已经核验公司。
- “登记状态”这样的单独报告标签仍可询问本公司的实际值，不强制分流为词典。
- 未收录且明确只问含义的词，要求用户提供所在句子；不让模型编造法律/金融定义。
- 超大案卷的**完整综合判断**仍可能触发覆盖保护。这次解决的是概念问题不该被整案预算阻塞，以及模糊投资需求不该直接读取全案，不宣称已无限支持全量综合评估。
