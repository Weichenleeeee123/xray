# 小企问答分流修复与发布验收

本次为代码修复，不是再增加模型预算。GitHub 合并不等于公网已部署，发布仍由部署队友按 [现有部署流程](deployment.md) 完成。

## 修复内容

1. **词义解释独立于案卷大小。** “什么是存续”“存续是什么意思”“请问存续是什么意思”“怎么理解存续”“能解释一下存续吗”“裁判文书是什么意思”等完整词义问题，使用人工词表直接解释，不调用大模型、不构建整案上下文。只解释概念，不夹带公司的成立时间、金额、状态或结论。
2. **修正错误词义。** 存续不是正常营业的保证；新增裁判文书解释；删除用股权出质、动产抵押条数推断企业缺钱的说法。[官方依据](2026-10-03-glossary-clarity-sources.md) 单独记录。
3. **先确认模糊投资需求。** “我投资这家公司怎么样”先问买股票、购买产品还是直接出资合作，不声称已完成投资评估。具体退款、收益、判赔等问题以及明确选中条目的问题，继续走原证据核对流程。
4. **解释与来源一致。** `ChatMessage` 新增向后兼容字段 `answer_kind` 和 `knowledge_terms`。新回答保存本次采用的词义快照；旧案卷不重写，新问答也不再使用旧的错误人工释义。前端右下角“原文出处”优先展示该回答自己的快照。
5. **明确展示回答类型。** 独立解释标为“名词解释”，需求澄清标为“先确认需求”，不把它们误标为模型异常后的基础答复。原始引用仍收在出处弹窗，不公开拦截内容。

## 未改变的边界

- 用户上传材料、完整案卷、公司规则结论、历史报告都不删除或重写。
- 版本和所选引用合法性检查先于分流；访客所有权仍由 API 校验。
- 普通企业问答的逐字引文、数字、确定性判定、来源和覆盖校验保持原规则。
- “存续是什么意思，这家公司安全吗”是混合问题，不能只答词义后冒充已经核验公司。
- “登记状态”这样的单独报告标签仍可询问本公司的实际值，不强制分流为词典。
- 未收录且明确只问含义的词，要求用户提供所在句子；不让模型编造法律/金融定义。
- 超大案卷的**完整综合判断**仍可能触发覆盖保护。这次解决的是概念问题不该被整案预算阻塞，以及模糊投资需求不该直接读取全案，不宣称已无限支持全量综合评估。

## 队友发布操作

1. 从 GitHub 拉取包含本修复 PR 的最新 `main`，沿用现有发布目录流程，保留旧发布版本便于回滚。
2. **同时发布后端和报告前端**：`backend/app/question_routing.py`、`assistant.py`、`conversation.py`、`models.py`、`glossary.json` 以及 `web/app.js`。推荐发布完整同一提交，避免漏文件。本次没有新 Python/npm 依赖，也没有首页动画改动。
3. 保留生产私有配置、访客签名密钥、持久化案卷/缓存/记忆目录。无需清空聊天、重建案卷、删记忆或更换模型；保持 Qwen3.8-Max 与现有长思考开关。
4. 确认无执行中的查询/问答后，切换发布目录并按现有流程重启 `qier`。只刷新浏览器或只修改环境变量不会加载新的 Python 路由。
5. 更新实际发布标识，核对 `/api/health` 的 `deployment.release_id`。浏览器强制刷新，确认加载新 `web/app.js`，然后**重新发送问题**；历史聊天不会自动改写成新答案。

## 公网验收清单

使用当前浏览器自己的已有案卷，无须重新花费额度查询公司。

| 操作 | 应看到的结果 |
|---|---|
| 杭州银行案卷问“什么是存续” | 主体仍然存在、不等于正常营业；不复述成立年限；标注“名词解释” |
| 改问“存续是什么意思”或“能解释一下存续吗” | 同样正确解释，不因问法变化回到朗读报告 |
| 华为等大案卷问“裁判文书是什么意思” | 解释法院文书、当事人角色与结果核对，不报整案上下文超限 |
| 点击上述回答右下角“原文出处” | 展示与新回答一致的解释、含义边界和依据，不出现旧“存续是正常经营” |
| 问“我投资这家公司怎么样” | 先确认股票、产品或出资合作；不假装已完成投资分析 |
| 问具体退款、核对金额、选中某条记录 | 继续引用真实案卷；缺依据时不能输出保证或伪造数字 |
| 刷新本浏览器后打开历史聊天 | 本次解释与其知识快照仍保持一致 |
| 用另一个访客身份请求相同案卷 | 仍不可读取案卷和问答 |

排查：若新问题响应无 `answer_kind`，先查后端发布版本；响应已有 `answer_kind` 但仍显示“当前为基础答复”，先查报告前端脚本和浏览器缓存。不要把历史那条错误消息当成新代码的测试结果。
