## 2026-10-04 追加：自然对话、报告词条上下文与受控工具

本节对应分支 `codex/xiaoqi-conversation-tools`，基于主线 `a32b3eb`。用户已授权推送并合并，本节记录实现与本地验收；GitHub 合并结果以对应 PR 为准。公网部署仍由队友执行，本轮没有执行或验证公网部署。

### 行为变化

- 普通生活和情绪表达进入自然对话，使用本案同版本最近八条对话，不读取完整案卷，也不要求用户提供公司、合同或业务名称。“我饿了 / 我想哭 / 我想睡觉”不再显示资料缺失、核验未完成或加入案卷按钮。模型不可用时有自然的基础回复，不伪造模型在线状态。
- 企业事实、金额、合同、安全判断、选中条目、完整核查及混合问题仍走原证据管道。企业话题的指代追问继承证据范围；明确切换到个人话题可正常聊天。清单与出处工具保留 `answer_scope=report_snapshot`，后续“继续”不能误变成无依据的企业评价。
- 发布复核补充：企业话题后经过“谢谢 / 好的 / 明白了”等礼貌确认，不会丢失核验范围；“我想知道还能撑多久”也不能仅因出现“我”就被当作闲聊。明确的情绪、饮食、休息、创作话题仍可自然切换。
- 一个受限调度调用可选择日常回复、读取本版报告、读取已有问题清单、打开既有出处、打开知识库或转交证据核验。不执行任意代码或外部写入，不让模型自行填写“已收藏”等成功回执。工具调用没有开放式循环。
- “期限备案”这样的本版 AI 补充词条也可直接解释，不再只查固定人工词表。人工词表优先，模型词条继续明确标注未人工复核；历史版本不借用其他版本的解释。未收录的词仍会请用户提供语境，不凭空造一个定义。
- 词条弹窗新增“问小企”，只填入可见、可编辑的问题；用户发送后才提问。输入区显示可取消的词条和版本标签。换案卷、换版本、离开页面、取消或转问无关问题时清理标签；网络重试保留原请求的上下文和幂等标识。
- “说简单点 / 举个例子 / 这个是什么意思”可延续最近词义；换说法仅使用词义资料，不送入公司原文。继续检查逐字依据、数字、原定义否定含义及企业断言，失败时保留原解释。收藏仍保存原解释的完整来源快照，不把新说法升级为人工知识。
- “加入案卷”不再由前端搜索建议文字生成，而由后端 `actions` 明确提出，仅适用于新的业务陈述。点击后只打开用户原话的可编辑草稿，须由用户提交才形成新分析；纯情绪不被视为新证据。
- 明确收藏指令补充“把刚才的解释记到我的知识库里”等说法，仍需要已有同版本词义快照。多词歧义、否定、条件句与混合调查不能自动保存；保存成功由实际存储结果决定。

## 2026-10-04 追加：聊天收藏词条

此前只有报告词条弹窗的收藏按钮，“将这一词收藏进知识库”会被误送入企业问答。本次接通明确的收藏操作，不增加模型调用，不改变资料核查规则。

- 小企名词解释下提供“收藏到知识库”和“查看知识库”。自然语言支持“将这一词收藏进知识库”“收藏这个词”“把刚才的解释记下来”“收藏实缴资本”等完整收藏指令。
- 服务器先校验案卷、版本与引用，再返回 `answer_kind=library_action`、`library_action={operation, terms, source_version, auto_save}`。该响应只是待执行动作，**不代表已经保存**。只有本次新请求、唯一明确的词条才由网页自动执行；多词指代不明时显示逐词按钮，没有可定位解释时要求先解释词语。
- 保存使用对应回答的 `knowledge_terms` 快照：完整解释、条件、依据、公司及原版本，不用当前词表偷偷替换旧解释。重复收藏不会取消或重复新增；同一词条 ID 的不同解释不静默覆盖，保留旧收藏并说明。相同解释在另一个报告或版本出现时，收藏按钮仍可点击以补记当前来源；只有解释和当前来源均已保存才锁定为“已收藏”。
- 写入结果由网页实际存储决定，区分“已保存到此浏览器”“已保存并同步到账号”“账号同步未完成”和存储失败。同步失败保留本地数据及待同步标记；账号同步成功必须收到服务器确认，不能把模型文字当成操作回执。
- 历史渲染、刷新、请求恢复不会重新执行收藏；已手动删除的词不会因打开旧聊天自动加回。导航代次、所选版本、身份与操作队列共同阻止旧请求在切页/切账号后继续执行。明确删除记录在同步重试中不会被远端旧列表复活。
- `/api/me/library` 的 GET/PUT 支持可选 `X-Xray-Library-Owner` 账号邮箱请求头：与当前登录身份不符时返回 409，阻止跨标签或异步响应造成错账号读写。不传头的旧客户端兼容；未登录仍需通过原认证检查。
- 保留用户材料、风险规则、数字与引用校验、访客隔离、报告历史及来源链接可读化。纯收藏命令不调用大模型，混合公司核查问题不被收藏路由吞掉。

## 2026-10-04 追加：日常了解与本版报告概览

### 问题与处理

此前只分出了词义解释和模糊投资需求。“听说华为是不是特别厉害呀”“你觉得华为怎么样”“你觉得这家公司怎么样”仍可能没有匹配到证据主题，随后被当成全案核查。大案卷因此在模型调用之前就触发覆盖保护；提高预算不能解决问法与读取范围不匹配的问题。

本次增加 `dialogue_routing.py` 和 `assistant_overview.py`：

- **先给有依据的报告概览，再继续问。** 常见整体印象、介绍、概览问题，以及同版本的概览追问，读取本版已生成的结构化报告，重算需求导向摘要，呈现背景、主要发现、重要异常及未覆盖部分。不是仅反问用户，也不是重读全部原文后给完整调查结论。
- **区分自然交流与事实核查。** “厉害”类问题会区分技术、产品、经营等维度；普通“怎么样”不会机械重复“厉害”的开场。已保存的研究目的继续使用，不反复要求用户重填。
- **不能识别范围时先澄清。** 按需读取模式下，没有命中事实主题、具体引用或明确完整核查要求的模糊问题，不再默认升级为全文审计；不把问题含糊解释成企业风险或资料缺失。
- **具体问题保留原核查。** 金额、退款、资质、财务、安全保证、选中条目、混合具体问题、完整核查等继续走原有证据链与上下文保护。概览后再问退款条件，仍读取关联条件和例外，不能沿用概览替代核查。
- **不借用别家企业记录。** 简称只是当前对话的主体提示，不验证品牌归属；明显切换企业时先确认，子公司、分支机构也不自动共享当前公司的依据。

### 引用、历史与隐私边界

概览只引用选定版本的报告条目和绑定公开记录。私有上传材料与用户评价不变成已核实企业事实；重复编号、失配或缺失出处明确保留核对提示。预制摘要仍复核版本、证据指纹、公开来源和有效内容，不按公司名称套用。全部严重异常保留，长条目不截取有利片段，而是保留完整原条目入口。原案卷、原材料及历史报告均不修改。

新增兼容字段 `answer_kind="overview"`、`answer_scope="report_snapshot"`；前端标注“本版报告概览 / 依据已生成报告”，出处仍放在回答右下角。旧回答不补写新标签或结论。同一秒返回的相同文本改按 `request_id` 区分，避免连续问题的回复被前端误去重；同一请求的重放仍去重。

## 修复内容

1. **词义解释独立于案卷大小。** “什么是存续”“存续是什么意思”“请问存续是什么意思”“怎么理解存续”“能解释一下存续吗”“裁判文书是什么意思”等完整词义问题，使用人工词表直接解释，不调用大模型、不构建整案上下文。只解释概念，不夹带公司的成立时间、金额、状态或结论。
2. **修正错误词义。** 存续不是正常营业的保证；新增裁判文书解释；删除用股权出质、动产抵押条数推断企业缺钱的说法。[官方依据](2026-10-03-glossary-clarity-sources.md) 单独记录。
3. **先确认模糊投资需求。** “我投资这家公司怎么样”先问买股票、购买产品还是直接出资合作，不声称已完成投资评估。具体退款、收益、判赔等问题以及明确选中条目的问题，继续走原证据核对流程。
4. **解释与来源一致。** `ChatMessage` 新增向后兼容字段 `answer_kind` 和 `knowledge_terms`。新回答保存本次采用的词义快照；旧案卷不重写，新问答也不再使用旧的错误人工释义。前端右下角“原文出处”优先展示该回答自己的快照。
5. **明确展示回答类型。** 独立解释标为“名词解释”，需求澄清标为“先确认需求”，不把它们误标为模型异常后的基础答复。原始引用仍收在出处弹窗，不公开拦截内容。

## 未改变的边界

- 用户上传材料、完整案卷、公司规则结论、历史报告都不删除或重写。
- 版本和所选引用合法性检查先于分流；访客所有权仍由 API 校验。
- 普通企业问答的逐字引文、数字、确定性判定、来源和覆盖校验保持原规则。
- “存续是什么意思，这家公司安全吗”是混合问题，不能只答词义后冒充已经核验公司。
- “登记状态”这样的单独报告标签仍可询问本公司的实际值，不强制分流为词典。
- 未收录且明确只问含义的词，要求用户提供所在句子；不让模型编造法律/金融定义。
- 超大案卷的**完整综合判断**仍可能触发覆盖保护。这次解决的是概念问题不该被整案预算阻塞，以及模糊投资需求不该直接读取全案，不宣称已无限支持全量综合评估。
