# 企业概况：从信任评级改为需求导向的企业发现

## 范围

初版输入是公司名及可选需求，只分析企业资料；材料上传、合同或 offer 核对仍属于独立材料分析。不修改模型、问答校验、收集接口、原始风险判定、记录分类、计数、雷达或案卷归属。无赞助商、知名企业的名称白名单。

## 新输出

`Version.overview` 保持 `schema_version: 1` 和原有 `status/counts/items`，新增可选 `summary`：

| 字段 | 用途 |
| --- | --- |
| `headline`（原字段） | 最重要且有依据的企业发现 |
| `summary.perspective` | 求职、机构核查、投资、合作、租房等阅读角度；没有需求则为综合核查 |
| `summary.explanation` | 含义、与本次目的的关系，以及不能直接推导的结论 |
| `summary.basis_ids` | 支撑摘要的本版企业条目 ID，前端直接导航至依据 |
| `summary.priority_ids` | 需要了解的全部企业条目，未进入标题的在“其他关注项”保留 |
| `summary.tone` | `neutral/attention/critical/unknown`，只表达发现的展示强度，不是信任等级 |
| `summary.rule` | 确定性摘要规则编号，便于排查与回归 |

为兼容旧前端，保留 `trust_*` 字段，但新结果固定 `trust_level=unknown`、`trust_label=headline`、`trust_note=""`，不再计算高低信任度。新前端以 `summary` 为准；读取旧案卷时，已有 `refresh_overviews` 路径会根据原版本事实重算，不覆盖原始材料或磁盘上的旧记录。

## 与预制示例的优先级

按用户确认，保留队友已合并的预制展示机制：有效的 `report_presentation` 优先于实时 `summary`。杭州银行预制示例继续显示“存在监管处罚，求职需结合具体岗位判断”及其定稿说明、正文和证据链接，不用新摘要覆盖它；异常计数、风险规则、原始记录不变。

预制文案只适用于服务器保存并绑定了证据指纹的指定版本，不能根据企业名称自动套用。普通实时查询即使查询同一家银行，也使用新的需求导向摘要。公司、需求、场景、证据或版本变化后，现有 `refresh_presentations` 校验会移除失效文案，回到普通摘要；仅重算 `overview` 不改变原始证据指纹。客户端还校验预制标记及本版出处，不同时显示两份相互竞争的主标题。

## 选择原则

1. 吊销等异常登记状态、严重违法失信、失信被执行等明确重要记录跨场景优先。其他正常项目再多也不能冲淡这些记录。
2. 随后优先选择本次需求相关的企业发现：求职看劳动争议与招聘，投资看披露数字，合作看执行及诉讼线索，消费和租房看投诉等线索。
3. 处罚是处罚，不是整家公司“不可信”；诉讼不等于败诉；投诉不是查实的违规。未阅读原文确定事项之前，不声称处罚与求职无关。
4. 正面语句限定到实际查过的来源。劳动仲裁显示“无”不能扩展为全部用工正常；历史劳动争议即使原规则标 `ok`，也不能说没有记录。
5. 金融机构名单匹配不扩展为“存款业务资质已核实”，因为现有字段可能匹配银行、信托、保险等不同名单。
6. 当前财务条目提供什么期间和数字，就展示什么；不编造连续增长、现金流趋势、未履约判决或欠薪事实。先前讨论的更细示例，只有未来获得足够结构化证据后才可以启用。
7. 所有原有记录继续保留。缺失、失败、不适用不当作正常；没上传用户材料不是首报缺陷。

## 实现与部署

- `backend/app/analysis/company_summary.py`：纯确定性生成，不新增大模型请求或收费查询。
- `backend/app/analysis/overview.py`：沿用企业信息范围，构建新摘要。
- `web/dossier-report.js`、`web/dossier/live.css`：阅读角度、大标题、解释及依据；材料入口标明后续可选。
- 前后端同时发布，重启后端并更新静态文件。`web/index.html` 已更新资源版本参数，避免浏览器继续使用旧摘要样式。
- 不需要提高上下文预算、修改密钥、重查企业或重建案卷。旧案卷打开时会重算派生摘要；预制包离线审计可能提示旧摘要需要刷新，此时不能修改其原始企业证据或来源日期。

## 回归

`backend/tests/test_company_summary.py` 覆盖同公司不同需求、处罚不等于低信任、严重事项不被正常项抵消、历史劳动记录、金融资质边界、投诉未核实、材料隔离和全部引用。

`backend/tests/test_report_overview.py` 继续验证原始分类、计数、缺口、权限、版本和只读重算。`backend/tests/test_demo_presentation.py` 验证重算摘要不破坏预制证据绑定。`web/tests/dossier-live.test.cjs` 检查新旧契约兼容、转义、原文跳转、材料入口、预制定稿优先及其失效后的实时回退。

`backend/tools/acceptance_company_summary.py` 会启动隔离的本地服务，创建标注为虚构的临时案卷，在 1440 / 1920 桌面宽度检查综合、求职、机构名单、资料不足、重要登记状态五种实时摘要，以及有效预制文案优先显示的第六种情况，并验证摘要依据与原文的真实浏览器点击。它关闭模型及外部查询，拦截意外外网请求，不读取或修改实际用户案卷，结束后停止测试服务，截图保留在输出的临时目录。
