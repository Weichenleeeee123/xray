# 证据采集清单（给队友，每家约 30 分钟）

2026-10-02补充：项目已带A/B的公开监管文书、上市公司年报摘录（`evidence_packs/*.json` 的 `extra` 段），可用于原始证据查看和助手引用。下面的工商、执行信息等清单**仍需人工核验**，不是已经完成。没有截图的公开摘录明确只提供原文网址和定位，不伪造截图。新证据包不会把年报数据冒充工商查询结果。

演示案例 A（杭州巨鲸财富管理有限公司）和 B（杭州银行股份有限公司）的登记信息，系统自己查不到：国家企业信用信息公示系统、中国执行信息公开网都有验证码，我们不绕。请人工查好，按下面的格式存成证据包。查完，报告里这些项就从"没查"变成真实记录。

系统已经自动查了下面这些，**不用再采**：
- 各份持牌名单
- 中基协私募登记和详情页（规模、员工、诚信信息、处罚）
- 监管、法院、政府网站上的文件
- 公开报道

## 1 怎么存

1. 复制 `backend/data/evidence_packs/_template.json`，改名为公司全称，例如 `杭州巨鲸财富管理有限公司.json`。
2. 只保留你查了的段：`registry`、`annual_report`、`extra`。
3. **删掉 `amac` 段**：中基协系统会自动查，填了也会被官方数据覆盖。
4. 删掉 `complaints` 和 `self_description` 段，除非你真的人工摘录了投诉、保存了公司官网原文。
5. 每段的 `source` 都要写清楚：
   - 网址
   - 查询时间（精确到分钟）
   - 截图路径：截图放进 `backend/data/evidence_packs/shots/`，文件名用"简称-内容.png"，例如 `巨鲸-登记.png`。
6. 原文照抄，不要改写。页面上没有的字段**整项删掉**，不要填 0 或"无"。系统把删掉的字段显示为"没查"；填了"无"，系统就会当成"查过，没有"。
7. 存好后重启后端，打开演示案例 A 或 B 重新生成，确认报告里那些项不再显示"没查"。

## 2 隐私规矩（仓库是公开的）

- **自然人股东不写真名**，写成"自然人股东A""自然人股东B"，`type` 填"自然人"。企业股东照抄全称。
- **不记**法定代表人、董监高的姓名、身份证号、住址、电话。
- 截图里有自然人身份证号、住址的，打码后再存。

## 3 案例 A：杭州巨鲸财富管理有限公司

统一社会信用代码 913301053281951475（来自公开资料，查询时请核对）。

| 查什么 | 去哪查 | 填到哪 |
|---|---|---|
| 登记状态、成立日期、注册资本、经营范围原文 | 公示系统 → 基础信息 | `registry.data`：`status`、`founded`、`reg_capital`（单位：元，例如 3174 万填 31740000）、`scope` |
| 股东及出资比例 | 公示系统 → 股东及出资信息 | `registry.data.shareholders`。重点看有没有国有企业、"金融集团"，它宣传说"获得国内大型综合金融集团的认可并注资" |
| 分支机构数量 | 公示系统 → 分支机构信息 | `registry.data.branches` |
| 行政处罚 | 公示系统 → 行政处罚信息 | `registry.data.penalties`（日期、机关、事由、结果） |
| 经营异常、严重违法失信 | 公示系统 → 列入经营异常名录信息 / 列入严重违法失信名单信息 | `abnormal`、`serious_illegal`：查了没有填 `false` |
| 股权出质、动产抵押 | 公示系统 → 股权出质登记信息 / 动产抵押登记信息 | `pledges`、`mortgages`：查了没有填 `[]` |
| 最近一年年报：实缴资本、参保人数 | 公示系统 → 年度报告 | `annual_report.data`：`paid_capital`（元）、`insured` |
| 被执行人、限制消费、失信 | 中国执行信息公开网 zxgk.court.gov.cn，按公司全称查 | 有被执行记录写进 `registry.data.executions`（每条写日期、执行法院、案号、金额）；被列为失信被执行人，`dishonest` 填 `true`；限制消费令写进 `extra` 一段（`source_id` 填 `court`） |

**特别注意**：商业网站显示它有"限制高消费"，这条**我们没核实**。请到执行信息公开网确认：
- 查到了，就照实写，并截图。
- 查不到，就写"查了没有"，不要采用商业网站的说法。

## 4 案例 B：杭州银行股份有限公司

| 查什么 | 去哪查 | 填到哪 |
|---|---|---|
| 登记状态、成立日期、注册资本、经营范围 | 公示系统 → 基础信息 | `registry.data` 同上 |
| 分支机构数量 | 公示系统 → 分支机构信息，数一下总条数 | `registry.data.branches`。它的招聘公告说"全行拥有200余家分支机构" |
| 前几大股东 | 公示系统 → 股东信息；上市公司股东多，抄持股最多的 5 个就行 | `shareholders`，在 `registry.source.note` 写"只抄了前 5 大股东" |
| 行政处罚、经营异常、严重违法失信 | 公示系统 | 同案例 A |
| 年报：参保人数 | 公示系统 → 年度报告 | `annual_report.data.insured`。银行在公示系统的年报里可能不公示，没有就删掉这项 |

核对案例 B 时，原招聘材料为2022届历史公告，不能把2025年末的机构数量直接当作同一日期、同一口径的核验结果。总行、分支机构、营业网点数量也不能混用。是否相符由证据决定，不预设案例应当得到正面结论。

## 5 不确定就问

拿不准某个字段怎么填，就留着不填，并在 `note` 里写清楚"某某项页面上有，但不确定怎么对应"。宁可显示"没查"，也不要填错。
