## 1 交给前端 Agent 的开工提示词

> 你负责企er 的前端。首页在 `research-room/`（React + TypeScript，静态构建），报告等业务页在 `web/`（原生 JS + CSS）。先读 PRD 第 2、5、7、8.1 节、本文和 `docs/research-home-integration.md`。契约以 `backend/app/models.py` 为准；`docs/sample-case.json` 是早期样例，缺少后加的字段。需要新字段先找后端，不要在前端自己拼假数据。改完用演示案例 C 把"查企 → 报告 → 点原始数据 → 问小企 → 补充信息 → v2"走一遍，再打印一页结论确认是一页 A4。

## 2 怎么跑

```bash
cd backend && .venv\Scripts\python -m uvicorn app.main:app --port 8000
```

先在 `research-room/` 执行 `npm run build:home`，再打开 http://localhost:8000 。根地址是研究室，`web/` 挂在 `/xray/`，同一个端口，没有跨域问题。改 `web/` 里的文件刷新页面就生效；研究室修改后重新构建；改了后端要重启。

- 首页未构建时显示 503 和构建提示；不会悄悄回退成旧首页。
- 不接模型也能用：需求识别退回关键词，助手退回模板回答，顶栏显示"未接模型"。

### 真实进度与等待动画（2026-10-02 联调）

- 旧完整材料表单新建案卷使用 `POST /api/cases/stream`，补充材料使用 `POST /api/cases/{id}/supplements/stream`。研究室首页使用可恢复的 `/api/runs` 任务接口；事件协议见 [progress-events.md](progress-events.md)。
- 流程：输入需求和材料 → 小企调研室等待动画 → 收到 `case` 事件后进入现有报告/版本。“小企调研室”不是另一套报告页。初始页视觉仍交由前端维护。
- `begin` 决定步骤，`step` 的实际开始/完成事件驱动动画；只显示已用秒数，不按定时器编造进度、百分比或查询条数。查了没有、没查、没查成分别展示。
- `ResearchProgress.mount(host, company)` 返回 `onEvent` 和 `stop`；`readCaseStream(url, body, {onEvent})` 只在收到完整的最终案卷后返回。断流不自动重发创建请求，提示查看案卷列表；后端可能仍在完成该次查询。
- 用户切换页面后，旧请求完成不会覆盖当前案卷。错误时保留完整输入；补充材料的进度放在弹窗可滚动正文内，防止移动端挤压表单。
- 两套等待动画复用 `research-room/public` 的资源，由后端将该目录挂到 `/research-assets/`。研究室首页需要先静态构建；正式运行只需启动后端。
- 本轮没有改动案卷上下文、引文/数字检查、风险规则或模型选择。密钥仅在后端忽略的 `.env` 配置，不能放进前端或提交 Git。

浏览器验收（在 `backend/`，需安装 `requirements-browser.txt`）：

```powershell
.venv/Scripts/python.exe -X utf8 tools/acceptance_browser.py
# 显式启用真实模型与企查查调用，会消耗对应服务额度：
.venv/Scripts/python.exe -X utf8 tools/acceptance_browser.py --live --commercial
# 复制此前验收缓存到新的隔离目录，避免重复付费查询公司：
.venv/Scripts/python.exe -X utf8 tools/acceptance_browser.py --live --commercial --seed-cache <上次验收目录>/cache
```

验收新建隔离案卷和评价目录，不修改真实用户案卷；检查真实流事件、两次二次分析、历史版本引用、模型回答的指定数字及出处、三份单页打印、手机宽度和断网回放。打印的页数与文字完整性自动核对，版面另行查看。`--live` 单独使用时不调用企查查，`--commercial` 才启用；企查查缓存命中与实时查询需分别解读，积分计数是代码估算而非平台账单。

## 4 页面

下表中的 hash 路由均位于 `/xray/` 下；旧的根地址报告书签仍会自动跳转。

| 路由 | 页面 | 用到的接口 |
|---|---|---|
| `/` | 研究室首页：叠加式公司输入框、默认公开资料研究、真实任务阶段与卷宗；右下角菜单提供其他入口 | `POST /api/runs`、`GET /api/runs/{id}`、`GET /api/cases/{id}` |
| `/xray/#/new` | 附带材料查询：公司全称、一句需求（停顿 0.8 秒自动识别场景，可改）、替谁看、金额、可选材料（粘贴或上传）；演示案例一键填入 | `GET /api/health`、`/api/scenarios`、`/api/sources`、`/api/demo/cases`；`POST /api/intake`、`/api/read`、`/api/cases/stream` |
| `#/cases` | 案卷：本机查过的公司及版本 | `GET /api/cases` |
| `#/me` | 我的：模型、商业数据源和名单状态，名词解释与使用底线 | `GET /api/health`、`/api/glossary`、`/api/cases` |
| `#/case/<id>` | 最新版报告，含评价页和小企 | `GET /api/cases/{id}`、`/api/cases/{id}/onepager`、`/api/reviews`；`POST /api/cases/{id}/chat`、`/api/cases/{id}/supplements/stream`、`/api/reviews`、`/api/cases/{id}/reviews` |
| `#/case/<id>/v/<n>` | 第 n 版报告；不是最新版时顶部有提示 | 同上 |

报告页的原则是"先给答案，细节按需展开"。从上到下：

1. 案卷头：版本切换（只有一版时不显示）、"补充信息"、公司名、需求原话，一行概况（场景 · 替谁看 · 金额 · 汇集了几条记录，点开跳到原始数据），版本备注。
2. 第一层 一眼看懂（首屏）：
   - 第一问的答案：场景的"第一问"（例如"它有没有资格收这笔钱？"），一个大号结论（✗ 有问题 / ! 要留意 / ? 还缺证据 / – 没查到 / ✓ 查过没发现问题）和最多 4 条记录依据。哪些条目回答第一问，写在场景配置的 `first_items` 里。
   - 它说的 ⟷ 记录里的：每条说法一行，左边是对方原话，右边是记录里的短句和判定。
   - 四个信号：四块小卡，各写最要紧的一句。
   - 下一步：先问对方的第一个问题。
   - 短句是报告生成时 AI 按规则原句缩写的（`v.glance.short`，见后端 `app/plain.py`），判定和颜色全来自规则；没有短句就显示原句。
   - "文字版（给家人看）"展开原来的一页结论，给家人 / 给网点柜员两个版本；打印只打文字版。三栏顺序是"哪里对不上 → 查到了什么 → 还不知道什么"。
3. 用图看（`v.charts`，后端 `app/analysis/charts.py` 从记录和规则算出，不经过模型）：注册资本说的 / 登记的 / 实缴的对比，承诺收益 vs 定存，宣称门店 vs 登记分支机构，股东构成，近 12 个月投诉，时间线。只画有数据的；没查的值画成虚线框写"没查"，不画成 0；不画风险分、雷达图、仪表盘；自然人股东不显示姓名；时间线只放处罚、监管措施、风险提示、法院文书（只写类别）、许可和最近几条投诉报道。每张图都能点到对应条目和原始数据。打印不带图。
4. 变化提示（第 2 版起）：一行字说明变了几项、没变几项，点了打开"变化"标签。
5. 标签页（吸顶）：变化 / 四个信号 / 宣称 vs 记录 / 该问对方的 / 原始数据 / 评价，每个标签带条数，有问题的显示红色。判断页仍为隐藏功能，只有地址加 `?judg=1` 才显示。
   - 四个信号：每张卡只列"有问题 / 要留意 / 该有的没有"的项；"没问题""没查"折叠成一行，点开才显示。卡片右上角写"N 项要看"；只有全部查过才写绿色的"查过的没问题"，有没查的就写灰色。
   - 宣称 vs 记录：一行计数，然后每条说法一张卡（原话、判定、一句人话、看原文）；"怎么查的"默认折叠。
   - 原始数据：每个来源单独标"查到了 / 查了没有 / 没查 / 查询失败"，整行点开是原始记录。
6. 报告里点任何编号（A1、risk.bank_list、Q1），都会切到对应的标签页、展开折叠的项，滚动过去并闪一下。

右栏是小企；查企、案卷、我的分区也保留这一栏，未打开案卷时只介绍可用功能。窄于 1280px 时收成右下角的"小企"按钮。

## 5 必须守住的规则（PRD 第 5 节在界面上的样子）

| 规则 | 界面上怎么做 | 代码位置 |
|---|---|---|
| 每条结论都能点进原始数据 | 来源角标 = 来源类型 + 数据日期 + 原始数据编号，点开是原始记录；记录里高亮对方原话，并列出报告里用到它的地方 | `srcTag`、`openRaw`、`backRefs` |
| 来源分类型标注 | 官方记录、人工采集、商业数据、法规、用户材料、网络公开、演示·虚构，各用一种颜色 | `KIND`、`.k-*` |
| 没查 ≠ 没问题 | 四种查询结果分开显示；"没查"用虚线 | `COVERAGE`、`.cov` |
| 虚构公司全程挂标记 | 顶栏、版本备注、原始数据、打印出来的一页结论上都有"演示数据 · 公司为虚构" | `isDemoCase` |
| 不把真实公司标成虚构 | 只有真查到了演示数据才算演示案例。真实公司"没查"的记录显示"没有数据"，不显示演示 | `rawKind` |
| 不打分、不定性 | 界面文案里没有安全分，也没有"安全""诈骗"之类的词；判定原词全部来自后端 | — |
| 对话不改报告 | 助手只回答；用户说了新情况，回答下面出现"加入案卷，重新判断"，点了才走二次分析 | `msgHtml`、`openSupplement` |
| 助手不越界 | 回答里的出处和逐字引文能点开；程序丢掉的出处数量、离线回放的录制时间都显示出来。模型推测后果或下定性时，后端让它重写（最多 2 次），界面折叠显示"程序拦下了越界说法，让模型重写了 N 次"和被拦下的原话 | `msgHtml`（`dropped`、`recorded_at`、`rewrites`、`blocked`） |
| 不显示假进度 | 新建和补充材料按后端实际事件展示步骤与覆盖结果，只显示已用秒数，不画百分比 | `ResearchProgress`；[进度事件契约](progress-events.md) |

## 6 约定

- 视觉上收着用：每一行只用左边一道色条表示状态，来源是一行灰字（类型 · 日期 · 编号），"问"按钮鼠标悬停才出现（触屏上常显）。不要给每一行再加徽章和边框。
- 可点的元素都写成 `data-act="动作"`，统一在一个 click 监听里分发。加新按钮就加一个 `case`。
- 报告条目的锚点用 `data-item="A1"`；按钮带的目标用 `data-id`。两者不能混用，否则点"跳到 A1"会跳到别的引用按钮上。
- 条目 id：`A1` 说法，`M1` 缺项，`risk.bank_list` 信号条目，`Q1` 问题，`R1` 原始数据。`R` 开头的打开原始数据弹窗，其他的滚动到报告里那一条并闪一下。
- 助手请求始终带正在浏览的 `version`（没有选中条目也带），不能用案卷最新版代替。报告选中项发送为 `v:1:assertion:A2`、`v:1:missing:M1`、`v:1:question:Q1`、`v:1:signal:risk:bank_list`；原始数据仍发 `R1`，由请求的 `version` 限定。旧案卷的裸编号仍能打开。
- 历史消息正文引用、用户针对项、`citations`、逐字引文和名词引用都绑定消息的 `version`；点击先切到该版，再定位条目或打开原文/该版名词解释。显式 `v:` 引用以其版本为准。切版清空选中项；助手请求失败只移除自己的临时用户消息，并且只有仍在原案卷原版时才恢复选中项和问题，避免切页后污染另一个版本。
- 前端版本协议回归：仓库根目录执行 `node --test web/tests/*.test.cjs`。测试在 VM 中执行实际前端函数，覆盖请求载荷、历史链接及失败时切版/切案卷；浏览器布局和端到端链路另行验证。
- 所有接口返回的文字都要经过 `esc()` 转义再插进页面。材料是用户贴的，里面可能有任何东西。
- 名词解释随报告一起生成，存在 `v.terms`：固定词表 `backend/app/glossary.json` 里的词，加上报告生成时模型补的词表外名词（`origin: "model"`，弹层和打印件上标"AI 解释"）。旧案卷没有 `v.terms`，前端退回 `GET /api/glossary`。报告里的标签、正文、对方原话、一页结论都会自动认出词表里的词（包括别名，长的写法优先），每块内容里每个词只标第一次，点开看解释和依据，手机上也点得开。打印一页结论时，页尾列出这页用到的词（最多 6 个）。要加词就改 `glossary.json`，后端的 `test_glossary.py` 会检查报告里的概念标签是否都有解释。

## 7 演示操作清单（F 负责操作电脑）

1. 演示前，用学校网络把完整路径走一遍。模型和搜索的响应会录进 `backend/data/cache/`。
2. 断网预案：`backend/.env` 里设 `XRAY_LLM_MODE=replay`，重启后端，顶栏显示"离线回放"；再不行就打开 `/demo/`。
3. 浏览器缩放调到投影上看得清；把小企右栏留在屏幕上（宽度 ≥ 1280px）。
4. 二次分析用补充信息对话框里的"演示案例准备好的补充"一键填入，不要现场打字。
5. 打印一页结论用浏览器打印，选 A4、不带页眉页脚。
