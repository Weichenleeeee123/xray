# X-Ray 前端交接（F）

- 依据：[黑客松版 PRD](2026-10-02-xray-hackathon-prd.md) 第 2、5、7、8.1 节。冲突时以 PRD 为准。
- 本文取代旧版交接文档（React + 登录 + SSE 那一套），旧方案作废，不要按它做。
- 现状：`web/` 已经实现 P0（F1–F6）和网点版、术语弹层，用演示案例 C 和真实公司（杭州银行）走通过。

## 1 交给前端 Agent 的开工提示词

> 你负责 X-Ray 的前端 `web/`。先读 PRD 第 2、5、7、8.1 节和 `docs/frontend.md`。技术栈固定：原生 JS + 一个 CSS 文件，不打包、不引框架、不加登录。契约以 `backend/app/models.py` 为准，返回样例见 `docs/sample-case.json`；需要新字段先找后端，不要在前端自己拼假数据。只改 `web/`。改完用演示案例 C 把"输入 → 报告 → 点原始数据 → 问助手 → 补充信息 → v2"走一遍，再打印一页结论确认是一页 A4。

## 2 怎么跑

```bash
cd backend && .venv\Scripts\python -m uvicorn app.main:app --port 8000
```

打开 http://localhost:8000 。后端把 `web/` 挂成静态文件，同一个端口，没有跨域问题。改 `web/` 里的文件刷新页面就生效；改了后端要重启。

- 后端启动时 `web/` 不存在，就会把首页跳到 `/docs`。遇到这种情况，重启后端。
- 不接模型也能用：需求识别退回关键词，助手退回模板回答，顶栏显示"未接模型"。

## 4 页面

| 路由 | 页面 | 用到的接口 |
|---|---|---|
| `#/` | 输入页：公司全称、一句需求（停顿 0.8 秒自动识别场景，可改）、替谁看、金额、可选材料（粘贴或上传）；演示案例一键填入；最近的案卷；每家都查的名单 | `GET /api/health`、`/api/scenarios`、`/api/sources`、`/api/demo/cases`、`/api/cases`；`POST /api/intake`、`/api/read`、`/api/cases` |
| `#/case/<id>` | 最新版报告 | `GET /api/cases/{id}`、`/api/cases/{id}/onepager`；`POST /api/cases/{id}/chat`、`/api/cases/{id}/supplements` |
| `#/case/<id>/v/<n>` | 第 n 版报告；不是最新版时顶部有提示 | 同上 |

报告页从上到下：

1. 案卷头：公司、需求、场景和第一问、替谁看、金额、版本切换、"补充信息"按钮、版本备注（虚构公司的红色提示在这里）。
2. 汇集结果：本版用到的每条原始数据一个标签，分别标"查到了 / 查了没有 / 没查 / 查询失败"。
3. 变化清单（第 2 版起）：变了的逐条列出前后对比、新信息原文和依据；没变的折叠列出；只改需求时写明"事实没变"。
4. 第一层 一页结论：给家人 / 给网点柜员两个版本，可以打印。
5. 第二层 四个信号：顺序跟着场景走；每行有状态、来源角标、"选中提问"。
6. 第三层 宣称 vs 记录：计数条、每条说法的判定和检查明细、该写却没写的内容；没有材料时显示补充入口。
7. 该问对方的问题：每条写明拿到答案后去哪查。
8. 第四层 原始数据：每条记录的类型、查询结果、数据日期、采集时间、备注。

右栏是 AI 助手；窄于 1280px 时收成右下角的"问助手"按钮。

## 5 必须守住的规则（PRD 第 5 节在界面上的样子）

| 规则 | 界面上怎么做 | 代码位置 |
|---|---|---|
| 每条结论都能点进原始数据 | 来源角标 = 来源类型 + 数据日期 + 原始数据编号，点开是原始记录；记录里高亮对方原话，并列出报告里用到它的地方 | `srcTag`、`openRaw`、`backRefs` |
| 来源分类型标注 | 官方记录、人工采集、商业数据、法规、用户材料、网络公开、演示·虚构，各用一种颜色 | `KIND`、`.k-*` |
| 没查 ≠ 没问题 | 四种查询结果分开显示；"没查"用虚线 | `COVERAGE`、`.cov` |
| 虚构公司全程挂标记 | 顶栏、版本备注、原始数据、打印出来的一页结论上都有"演示数据 · 公司为虚构" | `isDemoCase` |
| 不把真实公司标成虚构 | 只有真查到了演示数据才算演示案例。真实公司"没查"的记录显示"没有数据"，不显示演示 | `rawKind` |
| 不打分、不定性 | 界面文案里没有安全分，也没有"安全""诈骗"之类的词；判定原词全部来自后端 | — |
| 对话不改报告 | 助手只回答；用户说了新情况，回答下面出现"加入案卷，重新判断"，点了才走二次分析 | `msgHtml`、`openSupplement` |
| 助手不越界 | 回答里的出处和逐字引文能点开；程序丢掉的出处数量、离线回放的录制时间都显示出来。模型推测后果或下定性时，后端让它重写（最多 2 次），界面折叠显示"程序拦下了越界说法，让模型重写了 N 次"和被拦下的原话 | `msgHtml`（`dropped`、`recorded_at`、`rewrites`、`blocked`） |
| 不显示假进度 | 生成报告时列出这次真会查的来源，只显示已用秒数，不画百分比 | `createCase` |

## 6 约定

- 可点的元素都写成 `data-act="动作"`，统一在一个 click 监听里分发。加新按钮就加一个 `case`。
- 报告条目的锚点用 `data-item="A1"`；按钮带的目标用 `data-id`。两者不能混用，否则点"跳到 A1"会跳到别的引用按钮上。
- 条目 id：`A1` 说法，`M1` 缺项，`risk.bank_list` 信号条目，`Q1` 问题，`R1` 原始数据。`R` 开头的打开原始数据弹窗，其他的滚动到报告里那一条并闪一下。
- 所有接口返回的文字都要经过 `esc()` 转义再插进页面。材料是用户贴的，里面可能有任何东西。
- 术语解释写在 `TERMS` 里。标签和词条完全一致时，自动变成可点的术语，手机上也点得开。

## 7 演示操作清单（F 负责操作电脑）

1. 演示前，用学校网络把完整路径走一遍。模型和搜索的响应会录进 `backend/data/cache/`。
2. 断网预案：`backend/.env` 里设 `XRAY_LLM_MODE=replay`，重启后端，顶栏显示"离线回放"；再不行就打开 `/demo/`。
3. 浏览器缩放调到投影上看得清；把助手右栏留在屏幕上（宽度 ≥ 1280px）。
4. 二次分析用补充信息对话框里的"演示案例准备好的补充"一键填入，不要现场打字。
5. 打印一页结论用浏览器打印，选 A4、不带页眉页脚。

## 8 自测清单（每次改完走一遍）

- [ ] 只填公司名和需求能出报告；"宣称 vs 记录"显示补充入口
- [ ] 报告里任意一条都能点到原始数据，看得到来源、日期、真实还是演示
- [ ] 选中一条再问助手，回答里的出处点得开；问一个数据里没有的，答"没查到"
- [ ] 补一段对方回复生成 v2，变化清单里至少一项变了、一项没变
- [ ] 补无关材料，显示"没有影响判断的变化"；改需求为求职，显示"事实没变"，信号顺序跟着变
- [ ] 打印一页结论正好一页 A4，没有安全分和"诈骗"字样；虚构案例打印件上有虚构标记
- [ ] 真实公司（比如杭州银行股份有限公司）的报告上没有"演示数据"标记
- [ ] 手机宽度（375px）没有横向滚动，助手能打开
- [ ] 浏览器控制台没有报错
