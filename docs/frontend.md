# X-Ray 前端 F 执行交接

- 角色：一名前端，负责完整 Web 使用路径。
- 主文档：[X-Ray PRD](../superpowers/specs/2026-10-02-xray-prd.md)。冲突时以 PRD 为准。
- 技术方案：React、TypeScript、Vite、React Router、TanStack Query、ECharts。
- 主改目录：`apps/web/`。消费 `packages/api-types/` 的生成类型，不手改生成文件，不在前端保存 Tokendance Key。

## 1 交给前端开发 Agent 的开工提示词

> 你负责 X-Ray 的前端实现。先完整阅读项目 PRD 第 1—9、12—14、18—20 章和本交接文档，检查仓库现状，保留其他成员改动。目标是把全部批准功能做成可操作的公开网页，不自行砍功能，也不把 fixture 当真实结果。后端统一为 /api/v1，公共类型由后端 A 的 OpenAPI 生成。按 F-01 至 F-10 依赖顺序实施，每个工作包交付可运行页面、接口样例、通过的测试和未完成事项。先与 A 确认鉴权、错误信封、SSE 和首批类型，再建立所有主要路由与有明确标识的开发 fixture。不得调用供应商 API、暴露密钥或自行更改后端枚举。产品行为按 PRD，不要求先做视觉美化。

## 2 开工前与 A/B 对齐的内容

- A：开发 API 地址、同源代理、Cookie/CSRF 方案、OpenAPI 获取和类型生成命令。
- A：统一 `{data, request_id}` / `{error, request_id}` 响应；401、403/404、409、422、429 的实际处理。
- A：run 查询、SSE 订阅与恢复、上传及完成通知、文件授权预览接口。
- B：六种成果的匿名结构样例、判断状态、引用定位、上下文问答输入。
- 全体：测试账号只用于开发；演示资料有真实来源、用途许可和采集时间。

接口尚未运行时可以按冻结契约使用 fixture；界面必须显示开发数据标识，生产构建不得默认切到假成功分支。

## 3 第一批页面和组件

| 模块 | 必须可操作的行为 | 主要依赖 |
| --- | --- | --- |
| 账户 | 注册、登录、退出、改密、邮箱验证、找回与删除入口 | A：auth 与 session |
| 首页 | 搜索/筛选自己的 case，恢复、归档、复制、新建 | A：case API |
| 新建 | 自然语言→可编辑目标摘要；指定公司/发现候选/混合入口 | B：intake；A：case 创建 |
| 主体确认 | 区分品牌、法人和交易角色；有歧义请用户选择 | B：entity resolve；A：角色绑定 |
| 决策工作台 | 当前目标、主体、来源时间、判断和信息缺口 | A：assessment；B：分析内容 |
| 解释与引用 | 概念解释、原文定位、引用到助手；鼠标和键盘均可用 | evidence、explanation、selected_refs |
| 材料中心 | 文件/URL/文字导入，批次状态，识别纠错、撤回与删除 | A：uploads/documents；B：解析 |
| 判断变化 | 基础版/新版、改变与未变、影响范围、补核事项 | A：assessment diff |
| 成果 | 表格、比较、趋势、时间线、条款对照、核验清单 | artifact spec 与数据 |
| 后续管理 | 行动项、历史、私人资料复用、导出、关注和提醒 | A：对应资源接口 |

不要把工作台实现为一张静态报告再加聊天框。Agent 产生的新成果应保存到成果列表，材料变化应影响工作台当前版本。

## 4 组件层应固定的输入

1. `CaseContext`：case_id、场景、阶段、目标、约束、context_version、input_revision。
2. `AssessmentView`：assessment_id、version_no、依据截止时间、claim_versions、覆盖与缺失、artifact 引用。
3. `EvidenceReference`：证据 ID、来源标题、来源类型、原文定位、采集时间、可访问状态。
4. `RunView`：status、stage、阶段计数、最后事件 seq、错误和可执行操作。
5. `ArtifactView`：kind、status、based_on_version、结构化 spec、每项来源与计算记录。
6. `ChangeView`：前后判断、change.kind、影响解释、证据、待核验行动。

这些是组件消费概念，不是授权前端另造一套同名 API Schema；字段最终按 A 输出的 OpenAPI 对齐。

## 5 关键交互规则

### 5.1 任务与画像

- 不要求用户先填写完整主页；空画像也能完成研究。
- AI 解析的目标、预算、期限和优先事项可以修改并确认。
- 任务偏好优先于可选通用偏好；不能从一次问题自动永久记忆敏感特征。
- 显示本次使用了哪些画像/历史信息；关闭授权后后续问答不得继续携带它们。
- 修改条件后保留旧结果并标记待复核，不能直接将旧内容标成新条件的结论。

### 5.2 材料与引用

- 上传必须显示真实状态：上传中、服务端检查、解析、待确认、就绪或失败。
- 添加完毕调用批次封口；partial 也是解析结束状态，确认成功页后整批一次纳入。批次提交后新增成员另起批次。
- 多文件批次部分失败时让用户选择重试或按成功项继续，不静默忽略失败文件。
- 默认阈值见 PRD：25 MiB/文件、10 文件/批、PDF 100 页、粘贴文字 50,000 字符；读取后端实际限制。
- 图片定位使用原图归一化坐标，PDF 页码从 1 开始；缩放不改变 evidence 定位。
- 用户纠正识别结果后，标识“用户确认转录”，不是“材料真实性认证”。
- 撤回与彻底删除分开；删除需要明确确认，完成后旧消息和旧成果不得继续展示被删除私密内容。
- 不将私有文件 URL 放入第三方在线预览器。

### 5.3 问答与成果

- 引用消息提交 selected_refs 和用户问题；不要只把可见文字拼成没有版本的 prompt。
- 同时引用上限默认 10 条；跨版本引用显示版本，不伪装成当前判断。
- 流式内容未完成前是回答草稿，来源校验完成后才变成可点击引用。
- Agent 执行搜索、生成表格等动作显示工具回执；后端写回失败不得显示“已保存”。
- awaiting_user 展示批准/拒绝入口；确认后调用恢复接口。过期提议不能自动批准，服务端返回新 run 时切换订阅。
- 成果状态 current/updating/stale/failed/withdrawn 必须区分；旧图表明确标记依据版本。
- 数值缺失显示原因，不能画成 0；金额格式化不能改变精确原值。
- 每个比较单元格、趋势点、关键条款均应能追到来源或计算依据。

### 5.4 SSE 与恢复

- 使用认证会话订阅，不把 Token 放到 URL。
- 按 seq 去重和续接；断线先读取当前快照，再从后端指定位置恢复事件。
- 页面刷新不取消 run；取消是明确按钮和独立接口。
- 终态不可被迟到的进度事件改回运行中；收到终态后关闭连接。
- 多 run 并行时事件按 run_id 路由，不能串到另一个 case。
- 显示真实阶段与计数，不根据耗时生成虚假进度百分比。

## 7 前端自测清单

- 未登录访问私人路由不能看到上一个账号缓存；退出清除私有 Query 缓存和临时预览。
- A 用户复制 B 用户 case URL，页面不泄露 B 的标题、文件名或错误详情。
- 搜索没有结果、来源不可达、公开资料缺失、模型超时分别显示。
- 正常、部分、失败、取消、superseded 结果均能正确恢复。
- 修改条件期间旧结果可查，但新旧条件不混淆。
- 上传相同材料不会在成果中重复计算；并发上传能显示最终有效版本。
- 支持键盘打开解释、选择引用、关闭弹层；移动端无需鼠标悬停。
- 删除资料后立即清空该资料相关缓存与已打开预览，历史展示遵从后端脱敏状态。
- 导出结果包含任务、版本、时间、来源和范围，不包含 Key 或内部日志。
- 开发 fixture 关闭时不存在自动补假数据行为。
