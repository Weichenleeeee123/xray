# 企er产品使用指南

企er 帮你把企业记录、对方说法和自己的需求放在一起研究。这份指南介绍当前界面的使用方法；产品概览见 [项目首页](../README.md)，安装与配置见 [后端说明](../backend/README.md)。

## 先准备什么

准备公司名称和一句需求即可开始。公司全称最好来自营业执照、合同或收款信息；如果只有品牌名或简称，可以先搜索，再确认候选企业。

需求写清“准备做什么”和“最担心什么”通常比只问“靠不靠谱”更有帮助。例如：

> 收到这家公司的 offer，下周要入职，想了解经营情况，也想确认是否需要先交培训费。

初版报告不需要上传材料。有宣传、协议或对方回复时，可在报告生成后进入独立的“材料分析”。材料里的内容只作为待核对的说法，不会直接当成已经证实的企业事实。

## 1. 发起研究

打开小企研究室，输入公司名称。输入简称后，如果系统给出多个候选，按名称和可用的统一社会信用代码、成立日期等确认对象。没有找到时，补充营业执照上的全称；不要选择一家名字相近的企业代替。

“研究需求”选填。留空时查看一般企业信息；填写后，系统会围绕求职、预付消费、合作签约等场景组织关注点。正式首页不再提供“附带材料查询”入口；后续上传材料在案卷中单独分析。

提交后，小企会随着真实研究阶段在办公室中活动。墙上进度表达已经完成的环节，不是资料完整度、安全评分或剩余时间预测。暂停动画只影响展示，不会取消服务端查询。

报告保存并确认完成后，点击桌面报告册或“报告已就绪”入口查看。页面刷新后可以继续查看同一次任务；网络中断时优先使用“继续查看本次查询”，避免重复提交。只有重新发起查询才会创建新任务。

## 2. 阅读报告

建议按这个顺序阅读：先确认企业主体和需求，再看与需求有关的信号，最后打开依据并记录待问的问题。

| 页面区域 | 用途 |
|---|---|
| 企业概况 | 确认研究对象，查看概览与五维雷达 |
| 四个信号 | 查看风险、财务、信用、口碑中的具体记录与提示 |
| 问询与复核 | 看哪些问题需要继续确认，上传或补充相关材料 |
| 详细信息 | 查看当前取得的时间线、股东、资本等信息和用户评价 |
| 材料核对结果 | 对照材料中的说法和记录；有没有这一部分及其内容，取决于提交的材料 |
| 资料来源 | 展开来源目录，查看报告实际用到的记录、日期和可用的外部链接 |

五维雷达汇总的是已有条目的定性状态。某一维缺少信息时，不能据此判断企业表现好坏，也不能用图形面积给企业排名。

### 如何理解企业概况标题

标题直接说明本次查到的关键企业发现，说明文字解释它与你的需求有什么关系。系统不再因一条处罚就给整家公司贴“信任度较低”的标签，也不因为正常项目多而抵消严重记录。例如：

- 求职时，查到劳动争议：**发现劳动争议记录，入职需重点了解**。争议记录不等于已认定欠薪或败诉。
- 对应来源未查到劳动仲裁，但另有处罚：**所查劳动仲裁未见记录；发现行政处罚记录**。不是全部用工事项均已核实。
- 已查到金融机构名单记录，同时有处罚：**已查到金融机构名单记录；发现行政处罚记录**。名单匹配不等于所有业务资质有效，也不是资金安全保证。
- 只有登记资料：**登记信息已核实，其他关键资料仍待核实**。缺的是企业查询覆盖，不是要求用户先上传材料。

摘要下方可直接打开对应依据，“其他关注项”保留未进入主标题的重要记录。四类计数与雷达仍反映原始条目状态，不是公司评级。上述为规则示例，不是针对任何特定公司的结论。

### 区分四种查询状态

| 状态 | 实际含义 | 接下来怎么做 |
|---|---|---|
| 查到了 | 当前来源返回了相关记录 | 看记录内容、主体、日期及出处；查到记录本身不代表好或坏 |
| 查了没有 / 未查到 | 该来源的本次查询没有找到相应记录 | 留意查询范围和时效，必要时去原始网站核对 |
| 没查 / 未覆盖 | 本次未查询该项，可能缺少配置或数据能力 | 不据此判断有无问题；补充对应来源或材料 |
| 查询失败 / 没查成 | 发起了查询，但该次没有成功完成 | 看失败说明，待服务恢复后再核实 |

此外，材料中“没有写到”某个条款，与系统“没有查询”某个数据源是两回事。前者需要向对方要完整材料，后者需要补足查询覆盖。

### 查看来源时核对三件事

- **主体**：名称、签约方、收款方是否为同一家企业；集团或关联公司的记录不能自动算到当前主体上。
- **时间**：资料发布日期与报告生成时间不同，旧材料不能自动说明现在的状态。
- **类型**：官方记录、商业数据、网络报道、用户材料和用户评价应分别看待。外部链接能否打开还取决于来源网站和网络条件。

## 3. 向小企追问

在报告中展开小企，直接输入问题，或点击条目旁的“问”后再提问。例如：

- “这条提示对应的是哪份材料？”
- “目前还缺哪些信息？”
- “我该先向对方确认什么？”
- “这次补充后，为什么这一项变了？”

小企围绕正在查看的案卷版本解释；回答提供引用时，可以点开查看依据。旧版回答的引用仍对应旧版记录，不能直接拿来代表最新版报告。

小企的回答不等于已经修改报告。对话中提到新情况，需要通过 **“加入案卷”** 提交后才重新分析。没有配置模型或模型不可用时，回答可能退回模板，界面会显示相应模式。

## 4. 独立材料分析与需求更新

报告顶部的 **“补充材料”** 支持三类补充：

| 类型 | 适合提交的内容 |
|---|---|
| 新材料 | 新拿到的协议、宣传说明、公开文件等 |
| 对方回复 | 针对报告问题收到的回答，尽量保留上下文 |
| 改需求 | 金额、用途、关注点或使用场景发生变化 |

也可以从 **“拍照二次分析”** 进入材料复核。新材料和对方回复会生成独立的材料分析附页，保存在“问询与复核”底部，展示原文、核对结果和对原判断的影响。底层保留对应版本以便追溯，但不把材料结果替换为初版企业概况。改需求则更新公司报告的关注重点。旧版本和依据保留。

需求改变不代表企业事实改变。例如，研究目的从求职改成合作付款，报告关注点可能调整；这种变化应与新增经营记录引起的变化分开理解。

### 材料格式与读取限制

可以粘贴文字，也可以通过上传入口选择 TXT、DOCX、PDF 或常见图片格式（PNG、JPG、JPEG、WebP、BMP）。当前单个文件上限为 10 MiB，PDF 最多 50 页，图片最多 2000 万像素。

上传后先检查读取结果，再提交研究。PDF 中的扫描页、复杂排版、模糊图片或缺少可用的看图模型，都可能导致读取不完整或失败；按页面提示手动补充关键文字。读取成功只表示取得了文字，不表示材料内容已经通过核实。

## 5. 打印与回看

报告顶部点击 **“打印”**，选择“给家人”或“给网点柜员”，查看一页结论后进入浏览器打印预览。若浏览器支持，可以选择保存为 PDF。

一页结论保留关键事实、出入、未知项与下一步问题，适合沟通使用；它不是完整案卷的替代品。用户评价属于未核实的个人意见，不列入该页的企业事实。

从首页右下角菜单的 **“案卷”** 可以回到本浏览器访客身份创建的研究，查看报告各版本。案卷链接不是公开分享链接，换一个浏览器直接打开可能显示案卷不存在。

## 访客身份与公开评价

当前无需注册登录。系统使用签名 Cookie 识别浏览器访客，案卷、材料、任务和聊天在服务端按访客隔离。相同浏览器配置下使用本站的人可能沿用同一身份；这种机制不提供账号级的跨设备同步。

清除 Cookie、更换浏览器或设备、访客身份过期，都会影响原案卷的访问，当前没有自动恢复入口。部署者也需要保留服务端的访客签名密钥。访客隔离不等于数据只存本机，也不等于服务端无法读取数据。

只有主动提交的用户评价进入公开评价区。评价与私人材料的用途不同，提交前应确认希望公开的内容。启用外部模型与查询服务时，相关请求会交由配置的服务处理。

## 演示时如何选择模式

| 模式 | 能做什么 | 要事先准备什么 |
|---|---|---|
| 正常研究 | 按当前配置查询企业、读取材料、生成报告和问答 | 数据源与模型配置，以及对应网络和额度 |
| 预制示例 | 复用准备好的初始报告与指定顺序的补充版本，并回放研究进度 | 在演示环境生成或配置案例包；输入须与预设一致 |
| 模型回放 | 对匹配请求使用已录制的模型响应 | 缓存、相应案卷和相同请求上下文；其他数据查询仍需单独处理 |
| 静态演示 | 展示早期固定页面 | 本地 `/demo/` 页面，不提供完整实时功能 |

预制案例文件默认不随仓库分发。改动公司、需求或材料会进入正常研究；预制报告也不保证任意新提问能离线回答。准备方法见 [后端说明](../backend/README.md)，讲述顺序见 [路演操作单](demo-runbook.md)。现场应说明是在查实时资料，还是展示预先准备的研究。

## 常见问题

**为什么有些企业没有财务数据？** 公开财务资料的覆盖不同，上市、发债等公开披露主体更可能有相应记录。没有取得财务数据，不能推断财务状况好或坏。

**为什么看起来正常的企业也有提示？** 提示可能来自公开处罚记录、主体不一致、材料缺失或尚未完成的查询。需要打开具体依据，不能只看颜色下结论。

**“没查到问题”能不能理解成可以放心？** 不能。它只描述当前资料和查询范围，报告也不会给出安全担保。

**为什么查同一家企业，报告不完全一样？** 需求、补充材料、报告版本、来源日期和可用服务可能不同。比较时先确认这些条件，再看变化说明。

**为什么别人打不开我的案卷链接？** 案卷属于创建它的浏览器访客身份。需要沟通时，可以使用打印的一页结论；当前不提供公开案卷分享和跨设备账号同步。

**遇到报错，需要反馈什么？** 记录发生时间、页面操作、错误提示和任务编号，提供必要的脱敏截图即可。密钥、Cookie 和私人材料不应附在公开问题中。
