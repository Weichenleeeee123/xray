# 企业概况与路演案例核验

概况使用同一份适用公司记录生成标题、四类计数、展开依据和五维轮廓。一般关注记录与明确异常分开，查询失败和资料缺失不等于企业有问题。公司名称不参与判定，不为路演覆盖或改写异常事实。

## 离线审计工具

在 `backend` 目录运行：

```sh
.venv/bin/python tools/audit_demo_overviews.py data/demo_prebuilt \
  --expect-company 杭州银行股份有限公司 \
  --expect-company 华为技术有限公司 --format markdown

.venv/bin/python tools/audit_demo_overviews.py /path/to/saved-case.json --format json
```

Windows 可使用 `.venv/Scripts/python`。可以同时传入多个已保存案卷、预制包或只含这些 JSON 的目录。JSON 为默认输出；Markdown 便于排练记录。退出码 0 表示输入均通过结构检查，1 表示没有可检查的输入或存在结构错误。

工具只在内存中重算概况，不调用模型、搜索或商业资料接口，不重写输入文件。输出不含用户需求、聊天、材料正文或原始商业资料。它检查：

- 概况计数与可展开条目一致，异常标题必须有异常条目，已有异常不会变成好评；已有但失效的概况会提示刷新。
- 引用属于本版，原始记录编号能解析；已核查项目能回到本地资料或来源链接。
- 保留各来源的数据截止日期和采集时间；预制包生成日期、后续补充的单独生成日期不会混成同一个日期。
- 概况重算不改动报告原始记录、既有判断或预制来源。

`pass` 仅表示结构与引用一致，不能证明外部网页目前可访问、证据真实、资料完整或适合直接用于路演。`coverage_gaps_remain`、`source_date_unspecified` 和查询失败仍需逐项处理。已保存的普通案卷也不等于完整预制包。

## 准备可复现的演示

1. 确定准确公司主体与演示需求。先从已保存真实来源核对主体、日期、性质和处理结果，再补查关键缺口。保持“求职”“采购”“理财”等场景的不同核查范围。
2. 用项目现有 `tools/build_demo_bundles.py` 生成预制包。该旧工具会真实联网并可能消耗商业接口或模型额度；本轮没有运行它，也没有触发付费查询。商业资料包保持本地，不提交公共仓库。
3. 对包运行上面的离线审计。检查所有阶段，而不只看最后一版；人工核实每条触发主结论的记录，确认链接、公开原文与日期。
4. 实际打开界面，检查标题、计数、轮廓和引用跳转，保留“预制示例”和生成日期。未完成联网复核、浏览器演练或部署时，如实记录为待完成。
5. 如需演示合同带来的新发现，优先使用项目既有虚构公司 C 的演示合同。真实公司的公开历史材料与虚构交易条款必须清楚区分，不为真实企业编造回复或合同。

用户看见的正面信息应来自已核实的记录。预处理用于保证资料可追溯、演示可重复；它不改变企业结论。
