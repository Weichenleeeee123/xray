# 总览时间与事实说明优化

用户已批准三个小调整，由主代理直接实施，不使用子代理。

**Goal:** 保持一句主结论和简短解释，补足记录时间、一个相关事实及明细表述边界。

**Architecture:** 使用现有版本的信号和已绑定原始记录，确定性生成；不新增模型调用。仅更新派生摘要及状态展示文字，不修改证据、风险分类、计数或有效预制文案。

**Tech Stack:** Python/Pydantic，原生 JavaScript，pytest/node:test。

- [x] 添加回归：历史/近期/不明日期、原始记录范围、求职/合作/消费/综合需求、关键异常优先和预制绑定。
- [x] 摘要上下文使用明确事件日期，不能把采集时间作为事件日期。仅完整明细可支持全部为历史的措辞；不明日期和未取得的后续处理不能推断为已解决。
- [x] 解释先列本次事实，再说明边界；最多补充一项需求相关且已覆盖的事实，并带本版依据引用。严重事项仍优先。
- [x] 明细中正常状态但确有条数的记录使用中性“已查到记录”，保留原分类与颜色；未覆盖和不适用不受影响。
- [x] 跑相关后端/前端测试，用实际老板电器已保存资料离线重算，无需重复收费查询；检查原始资料和预制摘要不变。

范围之外：重建风险评分、大模型自由总结、公司名称特例、布局重做和重查数据源。

实际案卷验证：老板电器原始记录、信号、计数均未改动；摘要明确2016/2019年记录与所查明细近两年0条，同时引用2025年营收及同比。仅对明细完整、所有事件日期明确且距报告时间超过730天的劳动记录使用历史措辞；其他类型保留已知日期，不推断整改或结案。
