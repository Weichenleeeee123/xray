# 首页两级图片加载

用户要求保留高清图，同时缩短首页等待，并提交、推送修改。

采用现有 quality=90 WebP 作为第一层；第二层使用与 PNG 原图 RGBA 像素完全一致的无损 WebP。相比只使用压缩图，此方案恢复原图细节；相比直接加载 PNG，此方案先显示轻量版本，而且无损编码减少最终传输体积。保留全部现有文件。

页面初始资源加载结束后，等待浏览器空闲，再按背景、人物、环境、门、行走、访客、卷宗的顺序串行预取高清图，使用低网络优先级。每张图解码成功才切换；失败或超时保留预览，继续下一张。卸载页面时终止升级队列。背景、门叶和桌面/椅子遮挡共用同一图片状态，在同一次 React 更新中切换，保持尺寸、定位、动画及透明通道一致。

首屏继续 preload 轻量背景，不 preload 高清图片。缓存策略沿用当前部署：内容哈希 URL、图片一天、构建资源一年、HTML 重新验证、API 不缓存。此功能不消除网络/TLS 建连延迟，且完整加载的总流量会增加。

验收：验证无损图片像素一致；测试串行升级、解码失败回退及取消；构建与现有测试通过；真实浏览器确认先出现预览、后切高清且无布局位移，检查弱网/高清失败时页面可用。只增量部署首页，保留入口备份，不重启后端。检查提交范围和敏感信息后推送当前仓库。
